# 0.2.0 Access Query Language Normalization

Date: 2026-06-17

## Objective

Make the answer-first Access Query workspace read like a production operator workflow after a denied access answer. Backend decision payloads still contain stable English reasons, row messages, and next-action strings for compatibility, but the console should render business-readable localized copy.

## Scope

- Frontend-only change.
- No backend API contract change.
- No dependency change.
- Keep raw API results in state; translate at render time so language switching does not create stale language snapshots.
