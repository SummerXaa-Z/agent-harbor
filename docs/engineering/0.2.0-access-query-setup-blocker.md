# 0.2.0 Access Query Setup Blocker

Date: 2026-06-17

## Objective

Make Access Query explain why a live answer cannot run when required resources or capabilities are missing, and give operators the next safe workspace to finish setup.

## 中文说明

访问查询已经被定位为“先问一个具体访问问题”的主入口，但在空系统或资源未齐时，界面只显示空下拉和禁用按钮。对管理员来说，这不能回答“为什么不能查”和“下一步去哪”。本次增量在访问查询表单内增加轻量阻塞提示：缺租户、调用方或目标 Agent 时引导到资源管理；资源存在但目标能力为空时引导到工具能力。提示只在实时 API 已连接时出现，示例模式仍沿用原有接入提示。

## Scope

- Frontend-only access-query behavior and visual-system change.
- No backend API change.
- No new dependency.
- No access-decision request payload change.
- No automatic submission or mutation.
- All new user-facing copy is bilingual.

## Changes

- Added `askSetupBlocker` in `AskAccessView` to keep prerequisite routing local and deterministic.
- Added inline setup guidance inside the access-query panel when the form cannot become runnable because required live resources are absent.
- Linked missing tenant/caller/target resources to `#registry`.
- Linked missing tool capabilities to `#capabilities`.
- Kept the query button disabled until the existing `requestBuild.complete && liveDataAvailable && !loading` guard passes.
- Added compact warning-surface styling that reflows on narrow viewports without changing the primary question layout.
- Added EN and zh-CN copy for both setup-blocker paths.

## Notes

- This change intentionally does not start resource creation from Access Query. The query workspace stays answer-first, while setup work remains in Resource Management and Tool Capabilities.
- The blocker is not shown for sample data mode because that path already tells operators to connect the backend API before validating production access.
