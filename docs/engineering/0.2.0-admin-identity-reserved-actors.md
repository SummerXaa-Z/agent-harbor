# 0.2.0 Admin Identity Reserved Actors

Date: 2026-06-25
Branch: `codex/admin-identity-reserved-actors`

## Objective

Prevent built-in bootstrap and development principals from being reused as named bootstrap administrator actors.

## 中文说明

`admin-key` 和 `local-dev` 是 AgentHarbor 内部保留的管理主体名称。前者代表共享 `AGENT_HARBOR_ADMIN_KEY` 登录，后者代表显式开启开发绕过时的本地开发主体。

如果部署者把 `AGENT_HARBOR_ADMIN_IDENTITIES` 写成 `admin-key=...|role=platform_admin` 或 `local-dev=...`，运行时审计主体、审批人路由和引导身份解析都会变得含混。本轮把这两个 actor 名纳入解析期校验：具名管理员身份不能使用 `admin-key` 或 `local-dev`。

## Scope

- Bootstrap admin identity parser.
- Production deployment preflight.
- Production hardening scenario coverage.
- Runtime configuration docs, changelog, release checklist, and engineering note.
- No API route, frontend, storage schema, or dependency changes.

## Changes

- Added `reservedAdminIdentityActor` validation to `adminIdentitiesFromRaw`.
- Added focused parser and production preflight regression tests for reserved actor names.
- Extended `scenario-production-hardening.sh` to prove reserved named actors fail before PostgreSQL initialization and without leaking database credentials.
- Updated README, `.env.example`, release checklist, and changelog with the reserved actor contract.

## Notes

The rule is intentionally parser-level, so it applies consistently in development and production whenever `AGENT_HARBOR_ADMIN_IDENTITIES` is configured. It does not change shared `AGENT_HARBOR_ADMIN_KEY` behavior; the authenticated shared-key actor remains `admin-key`.
