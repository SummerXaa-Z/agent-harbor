# 0.2.0 AI Admin Browser Journey Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a release-grade check and first-run readiness UI for the browser-facing AI Admin approval journey.

**Architecture:** Keep the existing shell approval scenario as the source of truth for the permission-package data-plane flow. Add a browser-journey gate that starts API, mock MCP, and web console services, verifies the browser CORS subject-header preflight, then runs the approval-required scenario against those services. Add a small frontend readiness helper so AI Admin operators see API, Mock MCP, subject-header/CORS, private-upstream, and data-source readiness before running the live journey.

**Tech Stack:** Bash, curl, existing Go API, existing mock MCP server, Vite dev server, React/TypeScript, node:test frontend tests.
