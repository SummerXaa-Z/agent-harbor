# 0.2.0 Approval Request Lifecycle Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development when explicitly authorized; otherwise use superpowers:executing-plans or inline execution to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make approval-required permission package requests production-safe by expiring approvals and consuming each approved request exactly once.

**Architecture:** Keep the existing `pending`, `approved`, and `rejected` statuses. Add lifecycle metadata to each approval request: `expiresAt`, `consumedAt`, and `consumedByApplicationId`. The shared REST and management MCP apply path validates approved requests against the current draft, rejects expired or consumed requests before writes, and applies permissions through one repository mutation that conditionally consumes the approval request in the same PostgreSQL transaction or memory-store lock as capability updates, entitlement writes, application persistence, and audit evidence.

**Tech Stack:** Go domain types, memory and PostgreSQL repositories, HTTP API tests, Bash scenario scripts, frontend TypeScript types, release docs.
