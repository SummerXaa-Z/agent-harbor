# 0.2.0 Approval Reviewer Auth Binding

Date: 2026-06-25
Branch: `codex/approval-reviewer-auth-binding`

## Objective

Bind approval reviewer queue reads and management MCP approval resolution to the authenticated administrator identity.

## 中文说明

此前 REST 审批通过/拒绝路径已经会把 reviewer 绑定到认证管理员身份，但审批队列查询和管理 MCP 审批处理仍可能信任请求参数里的 `reviewer`。这会让一个已登录的非审批人查看其他审批人的待办队列，或通过管理 MCP 以其他 reviewer 身份处理审批。这个增量把所有传入 reviewer 的路径统一到 `reviewerFromRequest`，让读取和写入都使用同一个认证边界。

## Scope

- REST permission-package approval queue filtering with `reviewer=`.
- Management MCP approval queue filtering.
- Management MCP approve/reject reviewer resolution.
- Focused backend tests for requester-key reviewer impersonation.
- Changelog and README security notes.
- No frontend, schema, storage, or dependency changes.

## Changes

- `GET /api/v1/permission-packages/approval-requests?reviewer=...` now rejects a reviewer value that does not match the authenticated admin actor.
- `list_permission_package_approval_requests` in management MCP applies the same reviewer binding before returning a routed queue.
- `approve_permission_package_approval_request` and `reject_permission_package_approval_request` in management MCP now resolve reviewers through `reviewerFromRequest`, matching REST behavior.
- Development bypass behavior remains compatible: local development can still supply a reviewer explicitly when unauthenticated admin mode is active.

## Notes

This does not require reviewer routing to be configured. When no reviewer routing rules exist, authenticated reviewer identity still prevents self-reported reviewer impersonation, and the existing developer-preview fallback remains available only under explicit unauthenticated local development mode.
