# 0.2.0 Approval Reviewer Identity Preflight

Date: 2026-06-25
Branch: `codex/approval-reviewer-identity-preflight`

## Objective

Prevent production approval routing from starting with reviewer actors that cannot authenticate or should not review approvals.

## 中文说明

`AGENT_HARBOR_APPROVAL_REVIEWERS` 决定哪些审批人可以处理某个租户/工作区范围内的权限变更。此前生产预检只验证路由格式；如果路由里写了 `security-east=tenant-east/ws-support`，但没有对应的 `AGENT_HARBOR_ADMIN_IDENTITIES` actor，系统仍会启动，直到真正审批时才发现没人能以 `security-east` 登录处理。

本轮把审批路由和引导管理员身份打通：生产环境只要配置了审批路由，每个 reviewer 都必须匹配 `admin-key` 或一个 `AGENT_HARBOR_ADMIN_IDENTITIES` actor，且该身份角色必须是 `security_reviewer` 或 `platform_admin`。普通 `tenant_admin` 不能作为审批路由 reviewer。

## Scope

- Production deployment preflight for approval reviewer routing.
- Production hardening scenario coverage.
- Runtime configuration docs, changelog, release checklist, and engineering note.
- No API route, frontend, storage schema, or dependency changes.

## Changes

- `productionApprovalReviewersCheck` now validates reviewer actor authentication and role consistency after parsing route syntax.
- Added focused production preflight tests for missing reviewer identities and tenant-admin reviewer roles.
- Updated the valid reviewer preflight test to use realistic `security_reviewer` bootstrap identities.
- Extended `scenario-production-hardening.sh` to prove unbound reviewer routes fail before PostgreSQL initialization and without credential leakage.
- Updated README, `.env.example`, release checklist, and changelog with the stricter production contract.
