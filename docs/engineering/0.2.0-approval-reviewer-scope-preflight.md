# 0.2.0 Approval Reviewer Scope Preflight

Date: 2026-06-25
Branch: `codex/approval-reviewer-scope-preflight`

## Objective

Prevent production approval reviewer routes from being wider than the reviewer identity's tenant/workspace administration scope.

## 中文说明

审批人路由和管理员身份都表达了范围。如果 `AGENT_HARBOR_ADMIN_IDENTITIES` 把 `security-east` 限定在 `tenant-east/ws-support`，但 `AGENT_HARBOR_APPROVAL_REVIEWERS` 写成 `security-east=tenant-east/*`，路由范围就比该身份的管理范围更宽，容易造成审批边界与登录身份边界不一致。

本轮把这类配置纳入生产预检：平台管理员可以使用任意审批路由；范围化 `security_reviewer` 必须使用与身份相同的租户；如果身份限定了工作区，审批路由也必须限定到同一个工作区。租户级审批人可以使用该租户下的具体工作区或 `*`。

## Scope

- Production deployment preflight for approval reviewer routing.
- Production hardening scenario coverage.
- Runtime configuration docs, changelog, release checklist, and engineering note.
- No API route, frontend, storage schema, or dependency changes.

## Changes

- `productionApprovalReviewersCheck` now validates approval reviewer route scope against the matching bootstrap admin identity.
- Added focused production preflight tests for tenant mismatch and workspace widening.
- Extended `scenario-production-hardening.sh` to prove oversized reviewer routes fail before PostgreSQL initialization and without credential leakage.
- Updated README, `.env.example`, release checklist, and changelog with the route-scope contract.

## Notes

The preflight remains pure environment validation. It does not read tenant hierarchy from storage, so scoped reviewer routes must use the same tenant id as the bootstrap reviewer identity. Tenant-wide reviewers can still use `tenant/*`; platform administrators remain unscoped.
