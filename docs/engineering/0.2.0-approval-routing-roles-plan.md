# 0.2.0 Approval Routing Roles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a production-safe first slice of approval routing so configured reviewers can only list and resolve permission package approval requests inside their tenant/workspace scope.

**Architecture:** Keep approval requests unchanged in storage. Add deployment-level reviewer routing rules to the HTTP server and app config. REST and management MCP list operations can filter by `reviewer`; approve/reject operations validate the reviewer against configured tenant-subtree and workspace rules before changing request status. If no reviewer rules are configured, behavior remains compatible with the current developer-preview flow.

**Tech Stack:** Go HTTP API, app environment config, existing memory/PostgreSQL repositories, HTTP and app tests, README/product docs/changelog.
