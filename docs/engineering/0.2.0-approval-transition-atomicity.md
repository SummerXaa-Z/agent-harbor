# 0.2.0 Approval Transition Atomicity

Date: 2026-07-03
Branch: `codex/approval-resolution-atomic-transition`

## Objective

Make approval request approve, reject, and withdraw operations atomic at the repository boundary so stale concurrent handlers cannot overwrite a request that has already been resolved, consumed, or expired.

## 中文说明

审批处理原本是“读取待审批请求 -> 业务校验 -> 通用更新”。这能处理顺序请求，但在并发场景下，两个处理方可能同时拿到同一个 pending 快照；第一个请求完成后，第二个请求仍可能用旧快照执行通用更新，覆盖已经批准、拒绝或撤回的状态。

本轮把生产路径切换到仓储层原子状态转移：只有当前存储中的审批请求仍是 `pending`、未消费、未过期时，才能转为 `approved`、`rejected` 或 `withdrawn`。通用 `UpdatePermissionPackageApprovalRequest` 保留给测试造数和维护修正，不再作为审批处理的最终状态门。

## Changes

- Added `TransitionPermissionPackageApprovalRequest` to the repository interface.
- Memory storage now checks `pending + unconsumed + unexpired` while holding the repository mutex before writing the transition.
- PostgreSQL storage now performs the same transition with a conditional `UPDATE ... WHERE status='pending' AND consumed_at IS NULL AND consumed_by_application_id='' AND expires_at > now`.
- REST and management MCP approval approve, reject, and withdraw paths now use the transition method instead of generic update.
- When a stale transition loses the race, the server reloads the current request and returns a stable not-found, already resolved, already consumed, or expired validation error.
