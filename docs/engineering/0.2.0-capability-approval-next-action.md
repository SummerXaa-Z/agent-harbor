# 0.2.0 Capability Approval Next Action

Date: 2026-06-17

## Objective

Make Capability Governance keep operators on the safe next step after capabilities are discovered but before any capability is approved.

## 中文说明

工具能力刷新成功后，能力通常仍处于待审状态。此时主按钮如果直接展示“创建授权链”，会让管理员跳到一个尚未满足前置治理条件的操作。本次增量把能力页主动作改为状态驱动：空能力时刷新能力；只有待审能力时复核待审能力；至少一个能力已批准后才创建授权链。

## Scope

- Frontend-only Capability Governance behavior change.
- No backend API change.
- No new dependency.
- No automatic capability approval.
- No permission grant behavior change.
- All new visible copy is bilingual.

## Changes

- Added approved and pending capability derived state for the selected MCP target.
- Shows `复核待审能力 / Review capability approval` when the target has capabilities but none are approved.
- The review action filters the catalog to pending capabilities and opens the first pending capability detail panel.
- Capability details now show `批准 / Approve` for pending capabilities and `创建授权链 / Grant chain` only for approved capabilities.
- Added structural tests and i18n coverage to prevent the primary action from bypassing capability approval.

## Notes

- The review action intentionally does not approve automatically. It only narrows the catalog and opens the first pending capability detail so the administrator can inspect the risk and data scope before approving.
- Existing row-level approval remains available for operators who want to approve a specific capability directly from the table.
