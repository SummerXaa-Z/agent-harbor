# AgentHarbor 0.2.0 Cleanup Refresh Feedback Plan

## Goal

Make Agent status changes and policy cleanup operations report successful mutations accurately even when their follow-up resource refresh fails.

## Design Consensus

- Reuse the resource mutation refresh boundary introduced for create-key/create-agent operations.
- Extend the typed mutation action set to include Agent status changes and policy disablement.
- Keep the existing cleanup button busy state while separating mutation success from refresh staleness.
- Do not change backend APIs or audit contracts in this increment.

## Tasks

- [x] Task 1: Add focused regression tests for cleanup/status refresh feedback.
- [x] Task 2: Extend `managementMutationRefresh.ts` with status-change and policy-disable actions.
- [x] Task 3: Update `useManagementOperations` so Agent status changes and policy disables use the same post-mutation refresh boundary.
- [x] Task 4: Add EN and zh-CN refresh-failure messages plus changelog entry.
- [x] Task 5: Run focused frontend tests, frontend build, `make check`, and `make release-check`.
