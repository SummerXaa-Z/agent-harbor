# 0.2.0 Console Login Forwarded-For Trust

Date: 2026-06-17
Branch: `codex/login-rate-limit-forwarded-for-trust`

## Objective

Prevent direct clients from bypassing browser console login rate limiting by spoofing `X-Forwarded-For`.

## 中文说明

旧逻辑在登录限流分桶时直接信任 `X-Forwarded-For`。如果 AgentHarbor 没有放在会覆盖该请求头的反向代理之后，攻击者可以每次请求伪造不同的转发 IP，从而绕过失败登录限流。本轮把信任边界收紧为：只有请求来源是本机或私网代理时，才读取 `X-Forwarded-For`；直连公网来源始终按 `RemoteAddr` 计数。

## Scope

- Backend-only security hardening.
- No API contract changes.
- No UI or i18n changes.
- No new configuration or dependency.

## Changes

- Added `consoleLoginRemoteHost` to normalize `RemoteAddr`.
- Added `trustedConsoleForwardedForSource` so forwarded client IPs are trusted only from loopback or private proxy sources.
- Kept trusted local/private proxy behavior for deployments behind reverse proxies.
- Added regression coverage proving public direct clients cannot bypass login throttling by rotating `X-Forwarded-For`.

## Verification

## Notes

This is intentionally conservative. Deployments that need richer proxy trust policy can add explicit trusted-proxy configuration later; the safe default should not trust a client-controlled header from an untrusted remote address.
