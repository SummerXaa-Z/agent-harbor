# 0.2.0 Core Runtime Details Hierarchy

Date: 2026-06-17

## Objective

Make the expanded System Self-Check runtime details readable before exposing diagnostic identifiers. Operators should first see what runtime scope and decision are being verified, while run and tenant IDs remain available in a clearly labeled troubleshooting area.

## 中文说明

本次增量处理系统自检页的“运行明细”展开区：此前展开后直接看到运行 ID、租户 ID、允许工具和拒绝工具，仍然像排障面板。现在展开后先展示“运行范围”和“运行判定”两块业务摘要，运行 ID 和租户 ID 收束到“排障标识”区域，减少非技术用户的理解成本。

## Scope

- Frontend-only change.
- No backend API contract change.
- No self-check execution behavior change.
- No change to generated identifiers or runtime trace filters.

## Changes

- Replaced the flat four-column runtime detail grid with two operator-readable summary cards.
- Grouped raw run and tenant identifiers under a diagnostic identifiers section.
- Added bilingual labels for runtime scope, runtime decision, and diagnostic identifiers.
- Added regression coverage for the new runtime detail hierarchy.
