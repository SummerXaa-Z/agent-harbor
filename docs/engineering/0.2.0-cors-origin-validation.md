# 0.2.0 CORS Origin Validation

Date: 2026-06-23
Branch: `codex/production-cors-origin-validation`

## Objective

Reject invalid browser CORS origin configuration before AgentHarbor starts, especially in production mode where invalid or wildcard origins should be treated as deployment mistakes.

## 中文说明

`AGENT_HARBOR_CORS_ORIGINS` 是浏览器控制台访问 API 的边界配置。上一轮已经让生产模式不再默认放行本地开发来源；这一轮补齐配置质量校验，避免部署者写入 `*`、缺少 scheme 的域名、带路径的 URL 或非 HTTP scheme 后，系统仍然启动但浏览器路径表现异常。

## Scope

- App-level environment parsing for `AGENT_HARBOR_CORS_ORIGINS`.
- Production deployment preflight check for invalid CORS origins.
- Production hardening scenario coverage for invalid CORS origin rejection.
- README, `.env.example`, changelog, release checklist, and engineering documentation.
- No frontend, API route, storage, or dependency changes.

## Changes

- Added a shared CORS origin parser for environment configuration.
- Rejected wildcard origins such as `*`.
- Rejected entries without `http` or `https` scheme.
- Rejected non-HTTP schemes.
- Rejected user-info, path, query, or fragment in origin entries.
- Added `cors_origins_valid` to production deployment preflight.
- Added a production-hardening scenario assertion for invalid `AGENT_HARBOR_CORS_ORIGINS`.

## Notes

This validates syntax and origin shape, not ownership of the configured domain. Operators must still configure the production frontend domain deliberately and avoid sharing admin-facing CORS origins with untrusted applications.
