# 0.2.0 Credential Key Strength

Date: 2026-06-23
Branch: `codex/production-credential-key-strength`

## Objective

Reject obviously weak PostgreSQL credential encryption keys before they can protect persisted Agent credentials.

## 中文说明

`AGENT_HARBOR_CREDENTIAL_KEY` 是持久化 Agent 凭据的加密根密钥。之前只校验 32 字节长度，因此 `aaaaaaaa...`、全 0 base64 和文档里的 `0123456789abcdef0123456789abcdef` 都能通过。生产可用版本不能把凭据加密建立在示例 key 或低多样性 key 上。本轮把弱 key 拒绝放到 `internal/security.ParseCredentialKey`，让 raw 和 base64 输入统一受保护。

## Scope

- Credential key parsing in `internal/security`.
- App configuration tests for `AGENT_HARBOR_CREDENTIAL_KEY`.
- README, `.env.example`, changelog, and engineering documentation.
- No database schema changes.
- No API route contract changes.
- No frontend changes or new dependencies.

## Changes

- `ParseCredentialKey` now rejects:
  - repeated single-byte keys such as `aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa`;
  - repeated block patterns such as `0123456789abcdef0123456789abcdef`;
  - all-zero base64-decoded keys;
  - common weak raw strings such as repeated `password`.
- README PostgreSQL example now uses `openssl rand -base64 32` instead of a fixed sample key.
- `.env.example` now tells operators to use random raw bytes or base64.
