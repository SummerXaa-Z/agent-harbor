# 0.2.0 Effective Permission Explain Panel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a production-usable read-only effective permission explanation panel so administrators can understand why a tenant/workspace/caller/capability access decision is allowed or denied.

**Architecture:** Reuse the existing `EvaluateCapabilityAccess` repository path and the management MCP explain result shape. Add a REST endpoint for web clients, a typed frontend API helper, and a compact AI Admin/access-profile panel that renders outcome, blocking layer, evidence IDs, data scopes, and next actions. This slice does not add identity-provider integration, new policy writes, or mutable template recommendations.

**Tech Stack:** Go HTTP API, in-memory/PostgreSQL repository evaluation, React + TypeScript frontend, existing Node test runner, i18n dictionaries, README/product docs/changelog.
