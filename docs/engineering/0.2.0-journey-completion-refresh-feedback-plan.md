# AgentHarbor 0.2.0 Journey Completion Refresh Feedback Plan

## Goal

Make completed first-run and AI Admin runtime validation journeys survive follow-up refresh failures without being misreported as failed journeys.

## Design Consensus

- Keep backend and journey APIs unchanged.
- Treat successful MCP runtime validation as the journey completion boundary.
- Commit the runtime result before loading console data, tenant access profile, or audit rows.
- Use a shared pure refresh helper for post-completion refresh failures.
- Keep refreshed profile/audit data authoritative when available.
- If refresh fails, show a localized stale-records message and ask the operator to refresh before final go-live confirmation.
