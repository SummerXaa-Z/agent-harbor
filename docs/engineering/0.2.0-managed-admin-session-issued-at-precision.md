# 0.2.0 Managed Admin Session Issue Precision

Date: 2026-06-26
Branch: `codex/managed-admin-session-issued-at-precision`

## Objective

Preserve subsecond console-session issue precision so managed administrator sessions created immediately after key rotation are not rejected as stale.

## 中文说明

上一轮已经让托管管理员密钥轮换可以失效轮换前签发的浏览器 session。这里有一个生产边界：托管管理员的 `RotatedAt` 使用数据库时间戳，可能包含亚秒精度；旧 session payload 的 `issuedAt` 只保存 Unix 秒。如果管理员在同一秒内完成密钥轮换并重新登录，新的 session 可能因为被截断到这一秒的起点而看起来早于 `RotatedAt`，从而被误判为旧 session。

本轮把新签发的控制台 session 改为保存 Unix 纳秒时间戳，并在验证时兼容旧的秒级 `issuedAt` token。这样既能保持密钥轮换后的即时止损能力，又不会误踢轮换后立刻重新登录的管理员。

## Scope

- Console session payload issue timestamp precision.
- Managed administrator session verification compatibility.
- Deterministic HTTP API test clock for auth/session boundary tests.
- Changelog and engineering note.
- No storage schema, frontend layout, API route, or dependency changes.

## Changes

- New console sessions now store `issuedAt` with nanosecond precision.
- Session verification now accepts both nanosecond and legacy second-precision `issuedAt` values.
- Missing or zero `issuedAt` still falls back to `expiresAt - defaultConsoleSessionTTL` for legacy session compatibility.
- Added a deterministic `WithClock` server option for precise auth/session tests.
- Added coverage for same-second key rotation followed by login and session validation.
- Added coverage proving legacy second-precision session tokens remain valid when issued after the latest rotation.
