# 0.2.0 Management MCP Access Next Action Codes

Date: 2026-07-07
Branch: `codex/mcp-access-decision-next-action-codes`

## Objective

Make `explain_access_decision` usable by admin agents without parsing human-readable `nextActions`.

## 中文说明

访问查询解释已经能返回允许/拒绝原因、证据层和有效数据范围，但下一步仍只有自然语言 `nextActions`。管理 Agent 如果要自动判断“走权限包、补工作区授权、补调用方授权、收窄数据范围，还是无需变更”，不应该解析英文文案。本轮为 `explain_access_decision` 增加稳定 `nextActionCodes`，同时保留旧版 `nextActions` 兼容人类阅读和旧客户端。

## Codes

- `refresh_capabilities`: the selected capability is not registered on the target.
- `approve_capability`: the capability exists but is not approved for use.
- `use_permission_package`: the tenant has no entitlement; use the permission package flow to create the grant chain.
- `create_workspace_assignment`: the tenant entitlement exists but the workspace assignment is missing.
- `create_caller_assignment`: the workspace assignment exists but the caller instance assignment is missing.
- `narrow_data_scope`: requested child data scopes exceed a parent capability, tenant, workspace, or instance boundary.
- `review_deny`: a matching deny effect blocks access and needs explicit review before broadening access.
- `inspect_access_profile`: the denial reason did not match a known repair path; inspect the access profile for the first missing layer.
- `no_change_required`: the access decision is already allowed.

## Changes

- Added `nextActionCodes` to `managementMCPExplainAccessResult`.
- Derived access action codes from the existing `CapabilityAccessDecision` reason without changing access-evaluation semantics.
- Added backend assertions for denied and allowed access explanations through management MCP and the shared REST explain endpoint.
- Added scenario coverage for management MCP `explain_access_decision` before and after an approved permission package is applied.
- Updated product docs and changelog in English and Simplified Chinese.
