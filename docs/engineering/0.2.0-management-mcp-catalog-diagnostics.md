# 0.2.0 Management MCP Catalog Diagnostics

Date: 2026-07-07
Branch: `codex/management-mcp-catalog-diagnostics`
Confirmation schema extension: `codex/management-mcp-confirmation-schema-diagnostics`

## Objective

Expose the management MCP tool-catalog contract in the web console connection diagnostics, so operators can detect incompatible admin-agent tooling before automated write calls.

## 中文说明

`tools/list` 现在返回 `metadataVersion: 4`，并为每个管理工具提供 `safety`、`access`、`lifecycle`、`execution` 和写工具确认参数 schema。本轮把这个契约接入 Web 控制台的连接诊断：管理员运行诊断时，不只看到 API、实时数据和 MCP 工具服务是否可用，也能看到 Management MCP 管理工具目录是否具备当前 Agent 自动配置所需的安全、权限、生命周期、执行元数据和写操作确认参数。

## Behavior

- `metadataVersion: 4` with complete `tools[].safety`, `tools[].access`, `tools[].lifecycle`, `tools[].execution`, and write-tool confirmation schemas returns a ready diagnostic row.
- Missing version, empty catalog, or incomplete metadata returns a blocking diagnostic row.
- Unknown future metadata versions return a warning row, because automated write calls should pause for compatibility review.
- Tools that mutate state or advertise `execution.confirmationRequired` must expose an `inputSchema.confirmation` object requiring `confirmed` and `reason`.
- The public system-info compatibility summary must report a valid `catalogDigest` plus matching `toolCount`, `confirmationRequiredTools`, and `toolsWithConfirmationSchema` counts before the console treats the API as compatible.
- The hook reads the console session first so browser-session CSRF state is available before calling the management MCP endpoint.
- The decision logic lives in `frontend/src/connectionDiagnostics.ts`; the hook only fetches data and maps failures into diagnostic input.

## Changes

- Added management MCP catalog diagnostics to the connection-diagnostics model.
- Added `fetchManagementMcpToolsCatalog` for the browser console.
- Wired `useConnectionDiagnostics` to call management MCP `tools/list` after session refresh.
- Added English and Simplified Chinese copy for the new diagnostic row.
- Extracted the backend `metadataVersion` value into a constant.
- Updated product docs and changelog in English and Simplified Chinese.

## 2026-07-08 Confirmation Schema Extension

- Added frontend validation for confirmation-required write tools in the Management MCP catalog.
- Added a localized blocking diagnostic when write tools are missing the required `confirmation.confirmed` and `confirmation.reason` input schema.
- Extended the permission-package approval release scenario to validate the live `tools/list` confirmation schema before the scenario performs write calls.
- Bumped the catalog contract to `metadataVersion: 4` and `management_mcp_tools_metadata_v4`, so older v3 catalogs are rejected before automated writes.
- Added public system-info catalog summary counts and made API compatibility checks reject missing or mismatched write-confirmation coverage before protected catalog diagnostics run.
- Added a stable catalog digest to both system info and `tools/list`, and made the release scenario compare them before write calls.
- Kept the schema decision in `frontend/src/connectionDiagnostics.ts` so UI hooks and view components stay fetch/render only.
- Updated the product journey and changelog with English and Simplified Chinese notes.

## 2026-07-08 确认参数 Schema 扩展

- Web 控制台现在会校验 Management MCP 目录里需要确认的写工具。
- 写工具缺少必填的 `confirmation.confirmed` 和 `confirmation.reason` input schema 时，连接诊断会展示本地化阻断提示。
- 权限包审批发布场景现在会在执行写调用前，校验真实 `tools/list` 是否包含确认参数 schema。
- 目录契约升级到 `metadataVersion: 4` 和 `management_mcp_tools_metadata_v4`，旧 v3 目录会在自动写操作前被拒绝。
- system-info 公开摘要现在会返回工具目录计数，并在受保护目录诊断前拦截缺失或不匹配的写工具确认 schema 覆盖。
- system-info 和 `tools/list` 现在会返回同一个稳定目录 digest，发布场景会在写调用前比较两者是否一致。
- 判定逻辑继续保留在 `frontend/src/connectionDiagnostics.ts`，UI hook 和视图组件只负责请求与渲染。
- 产品旅程和 changelog 已同步补充中英文说明。
