# Management MCP Explain Tools Design

## Goal

Make the v0.2.0 AI Admin journey safer for non-technical administrators by letting an admin agent explain permission failures before it changes access.

## Design Consensus

This slice adds two read-only management MCP tools:

- `explain_permission_package_draft`: builds the same deterministic draft as `draft_permission_package`, then returns a concise explanation of readiness, blocked simulation rows, data-scope warnings, and suggested next actions.
- `explain_access_decision`: evaluates a specific tenant/workspace/caller/target/capability access decision, then returns the decision reason, evidence IDs, effective data scopes when allowed, and suggested next actions when denied.

The implementation does not add a new permission engine, persistence table, frontend page, or approval workflow. It reuses the existing permission package builder, capability access evaluator, and access-profile evidence model.

## Agent-Focused Output

Each tool returns the normal management MCP shape:

- `content[0].text`: compact JSON text for MCP clients that only read content.
- `structuredContent`: full structured JSON for agents and tests.

The structured response favors high-signal fields:

- `summary`: one sentence an admin agent can repeat to a human.
- `outcome`: `allowed`, `denied`, `ready`, or `blocked`.
- `decision` or `readiness`: source-of-truth backend result.
- `evidence`: IDs and short messages for the chain of capability, tenant entitlement, workspace assignment, and caller assignment evidence.
- `nextActions`: short, actionable remediation steps.

## Boundaries

The tools are under `POST /api/v1/management/mcp` and `/api/v1/management/mcp/rpc`, so existing `AGENT_HARBOR_ADMIN_KEY` protection applies.

The tools are read-only:

- They must not create entitlements, assignments, capabilities, traces, or audit events.
- They may call existing builders/evaluators.
- They must return JSON-RPC errors instead of REST envelopes when arguments are invalid.

## Acceptance Criteria

- `tools/list` includes both explain tools with strict input schemas.
- `explain_permission_package_draft` explains missing fields, blocked simulation rows, and data-scope readiness warnings.
- `explain_access_decision` explains denied access before a package is applied.
- `explain_access_decision` explains allowed access after a package is applied and includes effective data scopes and evidence IDs.
- Existing management MCP tools keep their response shape.
- `go test ./internal/httpapi -run 'TestManagementMCP' -count=1`, `git diff --check`, `make check`, local HTTP smoke, PR CI, and main CI pass.
