# 0.2.0 Management MCP Tool Access Metadata

Date: 2026-07-07
Branch: `codex/management-mcp-tool-access-metadata`

## Objective

Make management MCP `tools/list` describe who can call each admin tool, not only whether the tool mutates state.

## 中文说明

上一轮 `safety` 元数据解决了“这个工具会不会写状态”的问题，但管理 Agent 还需要知道“谁可以调、受什么范围约束”。这些边界后端已经强制执行：管理员身份生命周期要求平台管理员，权限包和资源工具受租户/工作区范围约束，审批通过/驳回会绑定审批人路由。本轮把这些既有边界沉淀为 `access` 元数据，帮助 Agent 在发起调用前做正确路由。

## Metadata

Each management tool now returns:

- `requiredRole`: `platform_admin` or `authenticated_admin`.
- `scopeBoundary`: `platform`, `global`, `requested_scope`, or `reviewer_route`.
- `reviewerBound`: true when the tool is bound to reviewer identity/routing.

## Changes

- Added `managementMCPToolAccess` and `managementMCPTool.access`.
- Added centralized access metadata injection for every management MCP tool.
- Marked administrator identity lifecycle tools as platform-only.
- Marked permission package, access explain, resource list, and access profile tools as requested-scope bounded.
- Marked approval resolution tools as reviewer-route bounded.
- Added backend and scenario assertions so missing or `unspecified` access metadata fails validation.
- Updated product docs and changelog in English and Simplified Chinese.
