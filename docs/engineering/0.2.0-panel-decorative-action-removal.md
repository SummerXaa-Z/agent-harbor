# 0.2.0 Panel Decorative Action Removal

Date: 2026-06-17

## Objective

Remove non-functional panel header actions from the web console so operators do not see button-looking controls that cannot complete a real task.

## 中文说明

本次增量继续收束控制台视觉和交互语义：多个信息面板标题右侧存在“打开 / 更多”图标按钮，但这些按钮没有绑定业务动作。对 B 端管理员来说，这会制造误导，让用户以为还有二级页面、菜单或隐藏操作。现在这些装饰性入口已移除，标题栏只保留真实可执行的操作，例如创建 Agent、创建密钥、轮换凭据和创建策略。

## Scope

- Frontend-only change.
- No backend API contract change.
- No data loading, table filtering, permission decision, resource mutation, or routing behavior change.
- Real modal actions and row-level operation menus remain unchanged.

## Changes

- Removed decorative `IconOpen` and `IconMore` usage from static panels including audit traces, management audit, route governance, acceptance history, runtime signals, contract matrix, capability governance, and tenant access profile.
- Removed the `IconOpen` and `IconMore` primitive exports so future panels cannot accidentally reintroduce button-looking controls with no handler.
- Kept `Panel` action support for real actions, including modal launchers and explicit resource operation buttons.
- Added a regression assertion that `ConsoleController` does not render `IconOpen` or `IconMore` as panel actions.

## Notes

- `OperationalViews` still uses a real More menu affordance for Agent row operations. That is intentionally preserved because it exposes actual status actions.
- This change should reduce visual noise on low-data pages and make the console action model clearer: a visible button means the operator can act.
