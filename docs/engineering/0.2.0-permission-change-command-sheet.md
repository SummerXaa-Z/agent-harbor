# 0.2.0 Permission Change Command Sheet

Date: 2026-06-17

## Objective

Make the Permission Changes workspace read like a production status workflow instead of an always-open draft form.

## 中文说明

权限变更页原来把完整草稿表单常驻在主路径里，用户进入页面会先看到一大段输入框、下拉和技术覆盖项，容易误判这是一个表单 Demo，而不是受控的权限变更流程。本次增量把“配置权限变更”的编辑动作收束成一个明确的按钮入口，并通过右侧独立面板打开完整配置。主页面默认只保留当前状态、租户/工作区/调用方上下文、处理流程、审批、应用和状态检查。

## Scope

- Frontend-only interaction and layout change.
- No backend API change.
- No permission package draft, approval, apply, validation, status-check, or access-profile semantics changed.
- The sheet is informational/editing UI only. Closing it does not submit, reset, or discard the draft.

## Changes

- Added `PermissionChangeDraftSheet` in `PermissionWorkbenchParts.tsx`.
- Replaced the always-visible permission draft form in `AiAdminPermissionWorkbench.tsx` with a single command entry.
- Kept all existing draft fields, business pickers, access subject selection, package preview, and technical overrides inside the sheet.
- Updated process navigation so the scope/template steps open the sheet instead of scrolling to an inline form.
- Updated locked and completed journeys so “新建权限变更” resets the draft and opens the sheet.
- Added bilingual copy and regression tests for the command sheet.
