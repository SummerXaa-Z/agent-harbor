# 0.2.0 Permission Package Application Health Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development when explicitly authorized; otherwise use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a read-only health summary for permission-package applications so administrators can see whether applied packages are still safe without opening each impact review manually.

**Architecture:** Reuse persisted `PermissionPackageApplication` rows and the existing impact calculation as the source of truth. Add `GET /api/v1/permission-packages/applications/health` to list recent applications in management scope and derive `ready`, `drifted`, or `needs_review` from impact summary and blocker codes. Render the result in AI Admin as a compact health panel that can load the selected application's existing impact review.

**Tech Stack:** Go HTTP API, memory/PostgreSQL repositories through existing list filters, React + TypeScript, existing Node test runner, i18n dictionaries, approval scenario script, README/product docs/changelog.
