# 0.2.0 Permission Package Application Impact Review Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a production-safe read-only impact review for permission package applications so administrators can see what an application created, whether those objects are still active, and what a future rollback review would need to check.

**Architecture:** Reuse persisted `PermissionPackageApplication` records as the source of truth, then resolve the recorded entitlement, workspace assignment, instance assignment, and capability ids against current repository state. Expose the assembled impact through a new admin-protected REST endpoint and render it in the AI Admin workspace next to the existing application evidence. This slice does not mutate permission state or implement rollback execution.

**Tech Stack:** Go HTTP API, in-memory/PostgreSQL repository filters, React + TypeScript frontend, existing Node test runner, i18n dictionaries, README/product docs/changelog.

- [x] Implement `getPermissionPackageApplicationImpact` as read-only:
  - Load the application through `ListPermissionPackageApplications` with `ID` plus `managementScopeFromRequest(r)`.
  - Return `404` if the id is missing or outside the requested tenant/workspace scope.
  - Resolve recorded tenant entitlement ids, workspace assignment ids, instance assignment ids, and allowed capability ids from current repository state.
  - Mark missing recorded objects as `currentStatus="missing"` and `rollbackAction="investigate"`.
  - Mark enabled grant objects as `rollbackAction="disable"`.
  - Mark capability rows as `rollbackAction="manual_review"` because package apply may approve shared capabilities that should not be automatically downgraded.
