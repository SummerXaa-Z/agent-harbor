# 0.2.0 Permission Package Apply Idempotency

Date: 2026-07-03
Branch: `codex/permission-package-apply-idempotency`

## Objective

Prevent direct permission-package apply retries from creating duplicate grant chains, application records, or audit rows after a client timeout, double submit, or network retry.

## 中文说明

审批路径已经通过审批请求消费语义防重：同一个已批准请求只能被消费一次，重复应用会返回 `PERMISSION_PACKAGE_APPROVAL_ALREADY_CONSUMED` 并引导控制台刷新状态。

无需审批的直接应用此前没有同等保护。如果客户端在第一次提交后超时，或管理员重复点击同一权限变更，后端可能再次创建新的租户授权、工作区授权、实例授权、应用记录和审计记录。本轮把直接应用也纳入存储层幂等边界：同一草稿、模板版本、租户、工作区、调用方、目标、访问对象、区域、数据范围和允许能力集合只允许应用一次。

## Changes

- Added `ErrPermissionPackageApplicationAlreadyApplied` as a stable store error for duplicate direct application retries.
- Memory storage now rejects duplicate direct apply attempts before mutating capability, grant, application, or audit state.
- PostgreSQL storage now takes an advisory transaction lock on the application duplicate key and checks existing application rows before writing any direct-apply mutations.
- REST apply maps duplicate direct applications to `409 PERMISSION_PACKAGE_ALREADY_APPLIED`.
- The console now handles `PERMISSION_PACKAGE_ALREADY_APPLIED` as a recovery state: refresh application health and status checks, then show localized guidance instead of a raw backend error.
- Added bilingual recovery copy for duplicate direct apply retries.

## Notes

The approval-required path intentionally keeps the existing consumed-approval behavior. That path already prevents duplicate application and has console recovery copy tied to `PERMISSION_PACKAGE_APPROVAL_ALREADY_CONSUMED`; changing it to the new direct-apply error would reduce operator clarity.
