# 0.2.0 Permission Package Drift Rehearsal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development when callable, otherwise use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a read-only drift rehearsal mode for permission-package application impact review so administrators can safely preview missing/inactive grant blockers and the remediation UI without mutating permissions.

**Architecture:** Reuse `GET /api/v1/permission-packages/applications/{id}/impact` and add an optional `rehearsal=grant_drift` query parameter. The backend computes the real impact first, then applies a response-only overlay that marks one workspace assignment missing and one instance assignment disabled when available. The response includes `rehearsal` metadata so UI and agents can clearly label the result as simulated.

**Tech Stack:** Go HTTP API, React + TypeScript frontend, existing Node test runner, i18n dictionaries, approval scenario script, README/product docs/changelog.
