# 0.2.0 Permission Package Remediation Plan Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development when callable, otherwise use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend the existing read-only permission-package application impact review with an operator-ready remediation plan so administrators can understand the safe manual sequence for capability review, grant disablement, drift investigation, and final effective-permission verification.

**Architecture:** Keep `PermissionPackageApplication` records as the source of truth. Reuse the current impact endpoint and add a structured `remediationPlan` field with `executionMode="read_only"`, `ready`, `blockers`, and ordered action rows. The API remains read-only; no rollback execution endpoint, mutation button, or automatic policy changes are introduced in this slice.

**Tech Stack:** Go HTTP API, existing repository reads, React + TypeScript frontend, i18n dictionaries, scenario shell script, README/product docs/changelog.
