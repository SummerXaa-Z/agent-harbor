# 0.2.0 Permission Process Gating

Date: 2026-06-17

## Objective

Keep the Permission Changes process panel aligned with the current operator step.

## 中文说明

权限变更草稿仍处于“申请待补充”时，主按钮已经提示“补全配置”，但右侧处理流程的状态检查区仍然展示后置的“执行运行验证”。这会让管理员误以为可以跳过配置、审批或应用权限，直接进入运行验证。本次增量让状态检查区复用当前旅程动作：权限尚未应用前只显示当前安全下一步；权限应用完成后才显示运行验证、状态检查和验收导出动作。

## Scope

- Frontend-only process-panel behavior and copy change.
- No backend API change.
- No approval, apply, runtime validation, status-check, or acceptance semantics changed.
- Existing applied permission changes still continue into runtime validation and status checks as before.

## Changes

- Added `goLivePrerequisitesReady` so the go-live/status panel only enters runtime actions after a permission application exists.
- Reused `journeyStatus.nextActionKey` in the status panel before prerequisites are met.
- Routed the status panel primary button through `runProductionPrimaryAction` when the current permission change is still in setup, approval, or apply.
- Added `text.runtimeValidationBlockedDetail` to explain that validation starts after permission application.
- Added regression coverage for process-panel gating and bilingual copy.
