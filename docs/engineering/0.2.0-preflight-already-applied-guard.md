# 0.2.0 Preflight Already-Applied Guard

Date: 2026-07-06
Branch: `codex/preflight-already-applied-guard`

## Objective

Move the duplicate direct permission-package apply protection into the read-only preflight path so operators and admin agents can see an already-applied permission change before pressing Apply.

## 中文说明

上一轮已经在存储层阻断重复直接应用，避免重复创建授权链、应用记录和审计记录。但应用前预检仍只提示“已有授权链”，并继续返回 `canApply=true`。这会让用户误以为还能再次应用同一权限变更。

本轮把同一套应用记录语义重复键复用到预检中：

- 手工导入或历史遗留的授权链仍然是 `existing_grant_chain` warning，管理员可以继续复核。
- 匹配到同范围应用记录时返回 blocking `application_already_applied`，阻止重复应用。
- 状态检查在已有匹配应用记录时会把 `application_already_applied` 视为应用后的正常预检状态，避免已上线链路被误判为 blocked。

## Changes

- Exported the store-level permission-package application duplicate-key comparison for read-only HTTP preflight reuse.
- Added `application_already_applied` to permission-package apply preflight when an existing application record matches the current draft, tenant, workspace, caller, target, access subject, region, data scopes, and allowed capability set.
- Preserved `existing_grant_chain` as a warning-only signal for legacy grant chains without application records.
- Kept production readiness compatible with the post-apply state by ignoring `application_already_applied` only when a latest matching application is present.
- Added English and Simplified Chinese preflight labels, details, and next-action copy.
