# 0.2.0 Preflight Next Action Codes

Date: 2026-07-06
Branch: `codex/preflight-next-action-codes`

## Objective

Make permission-package apply preflight machine-readable for the web console and management agents by adding stable next-action codes while preserving the existing human-readable `nextActions` field.

## 中文说明

应用前预检此前只返回英文 `nextActions`。Web 控制台可以通过本地映射兜底，但管理 Agent 和未来 UI 仍需要解析自然语言，这会放大 i18n 和兼容风险。

本轮新增兼容字段 `nextActionCodes`：

- `create_approval_request`: 需要创建并批准审批请求。
- `apply_permission_package`: 预检通过，可以进入应用权限。
- `use_approved_request`: 指定的审批请求不存在，需要使用匹配的已批准请求。
- `refresh_approval_request`: 审批请求过期、已消费、不匹配或仍不可用。
- `fix_draft_readiness`: 草案字段或就绪检查未通过。
- `narrow_data_scope`: 区域或数据范围超出能力边界。
- `review_existing_grants`: 存在历史授权链，需要复核。
- `review_current_application`: 匹配的权限变更已应用，需要查看当前状态而不是重复提交。

旧版 `nextActions` 继续返回，保证现有调用方不被破坏。Web 控制台优先使用 `nextActionCodes` 渲染预检下一步，只有连接旧服务时才回退到旧文案映射。

## Changes

- Added `nextActionCodes` to `PermissionPackageApplyPreflightResponse`.
- Centralized preflight next-action creation so code and legacy text stay paired.
- Covered REST and management MCP preflight structured responses with backend assertions.
- Updated the web console preflight type and presenter to prefer codes.
- Rendered the first preflight next action in the Permission Changes acceptance details using localized code mapping.
- Extended the permission-package approval scenario to assert next-action codes on missing approval, approved preflight, and already-applied preflight.
