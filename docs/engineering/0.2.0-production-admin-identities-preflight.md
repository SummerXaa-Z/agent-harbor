# 0.2.0 Production Admin Identities Preflight

Date: 2026-06-25
Branch: `codex/production-admin-identities-preflight`

## Objective

Validate configured named administrator identities during production deployment preflight, before AgentHarbor initializes PostgreSQL storage.

## 中文说明

`AGENT_HARBOR_ADMIN_IDENTITIES` 是生产审批、范围化管理员和职责分离的关键配置。它可以继续保持可选，但只要生产环境配置了具名管理员，系统必须在启动早期确认 actor、key、role、tenant/workspace 边界和重复项都可解析。否则管理链路可能带着错误角色或错误租户边界启动，等到审批或管理操作时才暴露问题。

## Scope

- Backend production deployment preflight.
- Shared admin identity parsing for preflight and runtime configuration.
- Production hardening scenario coverage.
- Runtime configuration docs, changelog, release checklist, and engineering note.
- No API route, frontend, storage schema, or dependency changes.
- Development-mode behavior remains compatible.

## Changes

- Admin identity parsing now flows through `adminIdentitiesFromRaw`, keeping production preflight and runtime startup on the same validation rules.
- Production mode now adds a blocking `admin_identities_valid` check.
- Named bootstrap admin identities now reject unknown roles in startup configuration parsing.
- Malformed configured admin identities fail before PostgreSQL connection, migration, or credential handling.
- `scenario-production-hardening.sh` now verifies malformed admin identities fail before an intentionally invalid PostgreSQL URL can be parsed or connected.
- README, `.env.example`, release checklist, and changelog describe the stricter production startup contract.

## Notes

This check validates configured bootstrap administrator identity syntax and boundary shape. It does not require named identities to be configured in production when `AGENT_HARBOR_ADMIN_KEY` is present, and it does not verify external identity-provider membership. Runtime requests still bind administrator actions to the authenticated admin key.
