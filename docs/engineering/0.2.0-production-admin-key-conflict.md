# 0.2.0 Production Admin Key Conflict Check

Date: 2026-06-23
Branch: `codex/production-admin-key-conflict`

## Objective

Reject production deployments where the shared bootstrap admin key and a named bootstrap administrator identity use the same secret.

## 中文说明

`AGENT_HARBOR_ADMIN_KEY` 是共享 break-glass 管理入口，`AGENT_HARBOR_ADMIN_IDENTITIES` 是具名管理员和审批人入口。两者如果复用同一把 key，就会让同一次登录或 API 调用对应多个可能身份：共享平台管理员、具名平台管理员或具名范围化管理员。即使当前认证顺序能选出一个身份，这种配置也会让审计主体、租户边界和应急访问语义变得不清晰。本轮在生产部署预检里直接阻断这类冲突，要求共享 key 与所有具名 bootstrap identity key 保持不同。

## Scope

- Backend production deployment preflight.
- Production hardening scenario coverage.
- README, release checklist, changelog, and engineering documentation.
- No API route, frontend, storage schema, or dependency changes.
- Development-mode behavior remains compatible.

## Changes

- Added `admin_key_uniqueness` as a production blocking preflight check.
- Production mode now rejects `AGENT_HARBOR_ADMIN_KEY` when it matches any parsed key from `AGENT_HARBOR_ADMIN_IDENTITIES`.
- The failure message names `AGENT_HARBOR_ADMIN_KEY` and `AGENT_HARBOR_ADMIN_IDENTITIES` but does not print the configured key material.
- `scenario-production-hardening.sh` now verifies the startup failure path and asserts the conflict log does not leak the configured admin key.
- Documentation now states that shared and named bootstrap administrator keys must be distinct in production.
