# 0.2.0 Production Admin Key Strength

Date: 2026-06-23
Branch: `codex/production-admin-key-strength`

## Objective

Block obviously weak bootstrap administrator keys before a production-mode AgentHarbor process starts.

## 中文说明

`AGENT_HARBOR_ADMIN_KEY` 和 `AGENT_HARBOR_ADMIN_IDENTITIES` 是产品外的 break-glass 管理入口。如果生产环境误用 `admin`、`secret`、`test-admin` 或很短的 key，即使后续的浏览器登录、CSRF、租户边界和审计都正确，也会留下最基础的管理面入口风险。本轮把弱引导密钥纳入生产部署预检：生产模式启动前阻断，开发模式保持兼容。

## Scope

- Backend deployment preflight model.
- Bootstrap shared admin key and named admin identity key validation.
- Web console production journey smoke cleanup after this increment exposed a release-gate hang.
- README, `.env.example`, and changelog documentation.
- No API route contract changes.
- No frontend changes or new dependencies.

## Changes

- Added `admin_key_strength` as a production blocking preflight check.
- Production mode now rejects:
  - bootstrap admin keys shorter than 16 characters;
  - common weak values such as `admin`, `secret`, `password`, `test-admin`, and `local-admin-key`;
  - weak keys in either `AGENT_HARBOR_ADMIN_KEY` or `AGENT_HARBOR_ADMIN_IDENTITIES`.
- Kept development-mode behavior unchanged so local demos and focused tests remain lightweight.
- Updated runtime configuration docs and `.env.example` with the production key-strength rule.
- Fixed `scenario-web-console-production-journey.sh` cleanup so successful smoke runs explicitly stop API, MCP, and frontend test servers and do not leave `make release-check` waiting on local service processes.

## Notes

This is a deliberately small deployment-hardening slice. It rejects clearly unsafe bootstrap keys without introducing a password-strength estimator, new dependencies, or a migration requirement for managed administrator identities stored inside the product.
