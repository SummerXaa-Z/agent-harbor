# 0.2.0 Production Credential Key Preflight

Date: 2026-06-25
Branch: `codex/production-credential-key-preflight`

## Objective

Validate the PostgreSQL credential encryption key before AgentHarbor touches production storage.

## 中文说明

`AGENT_HARBOR_CREDENTIAL_KEY` 是持久化 Agent 凭据的加密根密钥。生产模式已经要求 `AGENT_HARBOR_DATABASE_URL`，因此一旦启用持久化存储，凭据加密密钥也必须在数据库连接或迁移前通过校验。否则部署可能先触碰 PostgreSQL，再因为 key 缺失或弱值失败，形成半启动状态。本轮把生产凭据密钥校验纳入 deployment preflight，并把实际 key 解析移动到 PostgreSQL 初始化之前。

## Scope

- Backend production deployment preflight.
- Startup ordering before PostgreSQL connection and migration.
- Production hardening scenario coverage.
- Runtime configuration docs, changelog, release checklist, and engineering notes.
- No API route, frontend, storage schema, or dependency changes.
- Development-mode in-memory behavior remains compatible.

## Changes

- `deploymentEnvFromOS` now includes `AGENT_HARBOR_CREDENTIAL_KEY` so pure production preflight can validate it.
- Production mode now adds a blocking `credential_key_configured` check when `AGENT_HARBOR_DATABASE_URL` is configured.
- Missing or weak production credential keys fail before PostgreSQL connection or migration.
- `New()` parses the credential key before constructing the PostgreSQL pool in any mode where a database URL is configured.
- `scenario-production-hardening.sh` now verifies missing production credential keys fail before an intentionally invalid PostgreSQL URL can be parsed or connected.
- README, `.env.example`, release checklist, and changelog now describe the stricter production startup contract.

## Notes

This does not require PostgreSQL for local development or demo scripts that do not opt into `AGENT_HARBOR_DEPLOYMENT_MODE=production`. When a database URL is configured outside production, AgentHarbor still requires a valid credential key, but now fails before storage initialization.
