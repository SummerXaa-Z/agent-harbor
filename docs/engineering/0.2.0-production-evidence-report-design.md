# 0.2.0 Production Evidence Report Design

## Goal

Add a read-only production evidence report for the v0.2.0 AI Admin permission-package journey.

The report answers one operational question: after production readiness is checked, what exact evidence can an administrator or security reviewer hand off to prove why the package is ready, blocked, or needs review?

新增 v0.2.0 权限包旅程的只读上线证据报告。

这份报告回答一个运营问题：上线就绪检查之后，管理员或安全审查员可以交付哪一份证据，证明该权限包为什么可上线、被阻断或需要复核？

## Design Consensus

- The report is read-only and derived from the production readiness gate. It must not create approvals, apply packages, mutate grants, consume approval requests, execute remediation, or upload evidence anywhere.
- The backend remains the source of truth. AI Admin and management MCP request the report; they do not reconstruct readiness logic.
- The report is structured JSON, not PDF. JSON is deterministic, testable, agent-friendly, and safe to export locally without introducing document-rendering risk.
- The first slice includes evidence references and normalized scope, not full raw traces or unrestricted audit dumps. It should be useful for review while avoiding accidental data overexposure.
- The report supports the same production scope query as production readiness, including `traceLimit`.

## Response Shape

`GET /api/v1/permission-packages/production-readiness/report` returns:

- `reportVersion`: currently `production-readiness-report/v1`
- `generatedAt`
- `scope`: tenant, workspace, template, target, caller, subject, region, subject selector
- `status`: `ready`, `needs_review`, or `blocked`
- `summary`: readiness counts and evidence flags
- `checks`: stable check codes, severities, evidence ids, and messages
- `evidence`: compact references for latest application, health, impact, access profile, runtime traces, and applied audit event
- `nextActions`: ordered operator guidance
- `readinessGeneratedAt`: timestamp from the underlying readiness gate

## Management MCP

Add tool:

`export_permission_package_production_evidence`

It accepts the same arguments as `check_permission_package_production_readiness` and returns the same report shape. This lets an admin agent produce a bounded evidence handoff for non-technical administrators without calling each low-level endpoint separately.

## Frontend

AI Admin adds an action in the existing `上线就绪检查 / Production Readiness` panel:

- `导出证据 / Export evidence`
- Fetches the report from the backend.
- Downloads a local JSON file named from tenant, workspace, template, status, and timestamp.
- Shows success or failure inline in the panel.

Chinese labels must be first-class and must not fall back to English.

## Non-Goals

- No PDF or DOCX generation.
- No external upload or sharing.
- No signing, notarization, or immutable evidence store.
- No new persistence table.
- No frontend-only report generation.
- No raw unbounded audit or trace dump.

## Acceptance Criteria

- Before apply, the report returns `blocked` and includes the `application_present` blocker.
- After approval, apply, runtime allowed and denied calls, access profile, health, impact, and audit evidence are present, the report returns `ready`.
- `traceLimit=1` can still affect runtime evidence through the readiness gate.
- Management MCP lists and calls the evidence export tool.
- AI Admin displays a bilingual export action and downloads JSON only from live API data.
- The approval-required scenario validates blocked and ready report states.
- `make check` and `make release-check` pass.
