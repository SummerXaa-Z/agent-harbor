# 0.2.0 Production Platform Admin Preflight

Date: 2026-06-25
Branch: `codex/production-platform-admin-preflight`

## Objective

Require at least one bootstrap platform administrator in production deployment preflight so production environments retain a recovery administration path.

## 中文说明

`AGENT_HARBOR_ADMIN_IDENTITIES` 支持 `tenant_admin` 和 `security_reviewer`，但生产环境如果只配置范围化管理员，没有共享 `AGENT_HARBOR_ADMIN_KEY`，也没有任何 `role=platform_admin` 具名身份，首次部署、租户治理、管理员恢复和故障排查都会缺少平台级入口。

本轮把这类配置纳入生产预检：生产环境必须配置 `AGENT_HARBOR_ADMIN_KEY`，或至少一个 `role=platform_admin` 的具名管理员。范围化管理员仍然可以同时配置，但不能成为唯一的 bootstrap 管理入口。

## Scope

- Backend production deployment preflight.
- Production hardening scenario coverage.
- Runtime configuration docs, changelog, release checklist, and engineering note.
- No API route, frontend, storage schema, or dependency changes.
- Development-mode behavior remains compatible.

## Changes

- Added a blocking `platform_admin_configured` production preflight check.
- Shared `AGENT_HARBOR_ADMIN_KEY` satisfies the check as the existing bootstrap platform administrator.
- Named admin identities satisfy the check only when at least one parsed entry has `role=platform_admin`.
- Malformed named admin identity config remains owned by the existing `admin_identities_valid` check.
- `scenario-production-hardening.sh` now verifies tenant-only admin identity config fails before PostgreSQL connection, migration, or credential handling.
- README, `.env.example`, release checklist, and changelog describe the stricter production startup contract.
