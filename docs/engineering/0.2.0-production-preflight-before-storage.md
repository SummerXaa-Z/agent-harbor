# 0.2.0 Production Preflight Before Storage

Date: 2026-06-23
Branch: `codex/production-preflight-before-storage`

## Objective

Ensure invalid production deployment configuration fails before AgentHarbor initializes PostgreSQL storage, runs migrations, parses credential keys, or attempts a database connection.

## 中文说明

生产部署预检的目的，是在系统触碰外部状态之前拦截明显错误的配置。之前 `New()` 会先初始化 PostgreSQL，再执行生产预检；如果生产配置里已经有弱管理员密钥或开发开关，但数据库 URL 也存在，进程可能先尝试连接或迁移数据库。本轮把纯环境配置解析和生产预检前移到存储初始化之前，让错误配置先失败，减少部署事故半径。

## Scope

- Application startup order in `internal/app`.
- Regression test proving production preflight wins over invalid PostgreSQL configuration.
- Production hardening scenario coverage for preflight-before-storage behavior.
- README, changelog, and engineering documentation.
- No API route, frontend, schema, or dependency changes.

## Changes

- `deploymentModeFromEnv` and `deploymentConfigPreflightFromEnv` now run before repository construction.
- Pure environment parsing for private upstreams, approval reviewers, admin identities, unauthenticated admin mode, and CORS origins runs before storage initialization.
- PostgreSQL pool construction, migrations, and credential-key parsing now happen only after deployment preflight passes.
- `scenario-production-hardening.sh` now verifies a weak production admin key fails before an intentionally invalid PostgreSQL URL is parsed or connected.
