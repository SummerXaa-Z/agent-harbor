# 0.2.0 Production Readiness Gate Design

## Goal

Add a read-only production readiness gate for the v0.2.0 AI Admin permission-package journey.

The gate answers one operator question: can this tenant, workspace, caller instance, MCP target, subject, and permission package be treated as production-ready right now?

新增 v0.2.0 权限包旅程的只读上线就绪检查门禁。

这个门禁回答一个运营问题：当前租户、工作区、调用方实例、MCP 目标、主体和权限包，现在是否可以视为生产可用？

## Design Consensus

- The gate is a read-only aggregator. It must not create approvals, apply packages, mutate grants, consume approval requests, execute remediation, or rehearse drift.
- The backend is the source of truth. The frontend and management MCP display the gate result, but do not recompute safety.
- The gate reuses existing evidence paths: apply preflight, permission package application records, application impact, tenant access profile, runtime traces, and applied audit events.
- The gate returns stable status and check codes so AI Admin, admin agents, scripts, and docs can reason about the same result.
- The first slice focuses on the primary production journey, not a scheduler, notification engine, rollback executor, template marketplace, or custom policy authoring system.

## Status Model

The gate returns one of three statuses:

- `ready`: all required production evidence is present and current.
- `needs_review`: no hard blocker is found, but the operator should review warnings before claiming production readiness.
- `blocked`: required evidence is missing, stale, drifted, or contradicts the requested scope.

The response also includes:

- `summary`: counts and booleans for quick UI display.
- `checks`: ordered checks with stable `code`, `severity`, `message`, and optional evidence ids.
- `latestApplication`: the selected permission package application when one exists.
- `preflight`: the read-only preflight result for the requested package input.
- `applicationHealth`: the latest health row for the selected application.
- `applicationImpact`: read-only impact review for the selected application.
- `accessProfile`: tenant access-profile evidence for the requested scope.
- `runtimeEvidence`: recent allowed and denied trace evidence.
- `auditEvidence`: applied audit event evidence.
- `nextActions`: ordered operator guidance.

## Required Checks

The initial gate covers these checks:

- `preflight_ready`: latest read-only preflight can apply the current package request.
- `application_present`: an application record exists for the tenant subtree, workspace, template, target, and caller.
- `application_scope_match`: selected application matches the requested tenant, workspace, template, target, and caller.
- `application_health_ready`: latest application health is `ready`.
- `impact_ready`: read-only impact review reports rollback-review readiness and no missing created objects.
- `access_profile_chain_present`: tenant access profile contains at least one grant chain for the target, caller, and an allowed capability.
- `runtime_allowed_trace_present`: recent runtime evidence includes at least one allowed trace for the caller and target.
- `runtime_denied_trace_present`: recent runtime evidence includes at least one denied trace for the caller and target.
- `applied_audit_event_present`: audit evidence contains `permission_package.applied` for the selected application id.

## API

Add:

`GET /api/v1/permission-packages/production-readiness`

Query fields:

- `tenantId` required
- `workspaceId` required
- `templateId` required
- `targetId` required
- `callerInstanceId` required
- `subjectId` optional
- `region` optional
- `requestText` optional
- `subjectSelector` optional
- `approvalRequestId` optional
- `traceLimit` optional, default 20, maximum 100

The request is read-only. When `subjectSelector`, `region`, or `requestText` are omitted, the gate derives them from the latest matching application when possible. This lets the gate inspect an already-applied package without requiring the operator to re-enter every draft field.

`traceLimit` bounds the recent runtime trace evidence inspected by the gate. A value of `0` disables runtime evidence collection and therefore prevents a production-ready result until runtime evidence is checked again.

## Management MCP

Add tool:

`check_permission_package_production_readiness`

It accepts the same arguments as the REST query and returns the same response. This makes the platform AI-friendly: an admin agent can ask for a production go/no-go answer without learning each lower-level endpoint.

## Frontend

AI Admin adds a `上线就绪检查 / Production Readiness` panel near application health and impact review.

The panel shows:

- overall status badge
- blocker/warning/ready metrics
- latest application id
- runtime allowed/denied evidence state
- applied audit evidence state
- ordered blocker list and next actions

Chinese labels must be first-class, not fallback English.

## Non-Goals

- No write-path mutation.
- No automatic rollback.
- No background scheduling.
- No notification routing.
- No custom tenant policy authoring.
- No new persistence table.
- No frontend-only readiness inference.

## Acceptance Criteria

- Before apply, the gate returns `blocked` with `application_present`.
- After approval, apply, runtime allowed and denied calls, access profile, health, impact, and audit evidence are present, the gate returns `ready`.
- Management MCP lists and calls the same readiness tool.
- AI Admin displays the gate in English and Simplified Chinese.
- Scenario verification proves the blocked-before-apply and ready-after-evidence states.
- `make check` and `make release-check` pass.
