# 0.2.0 Readiness Copy Fallback Hardening

Date: 2026-06-17

## Objective

Keep the permission-change and go-live status journey readable when the backend introduces a new readiness check, preflight check, policy reason, or warning string that the current console has not mapped yet. Unknown service strings should not appear verbatim in the primary operator path; the UI should show a localized, business-readable fallback and keep the API contract unchanged.

## 中文说明

本次目标是收紧“状态检查 / 应用前预检 / 策略门禁 / 草案就绪”里的未知后端文案兜底。后端仍然可以返回稳定的 code 与 message，但控制台主路径不再直接展示未映射的英文句子或技术字段，而是统一展示“需要复核”的产品语义。

## Scope

- Frontend-only change.
- No backend API contract change.
- No dependency change.
- Keep translated copy at render/presenter boundaries, not in stored state.
- Continue reducing `ConsoleController.tsx` by moving reusable presentation logic into `permissionWorkbenchPresenters.ts`.
