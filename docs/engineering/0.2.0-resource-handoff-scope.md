# 0.2.0 Resource Handoff Scope

Date: 2026-06-17
Branch: `codex/resource-handoff-scope`

## Objective

Prevent Resource Management action handoffs from pre-filling permission changes with callers or targets from another tenant or workspace.

## 中文说明

资源管理页会把“需要授权”的资源带到权限变更流程。旧逻辑在当前资源缺少同范围调用方或目标服务时，会退回到全局第一个 Agent，这在多租户场景下可能把其他租户或工作区的资源带进权限变更草稿。本轮取消这种跨范围回退，缺少同范围对象时保持字段为空，让权限变更页要求管理员补全配置。

## Scope

- No backend changes.
- No UI copy or i18n changes.
- No new dependencies.
- Only the Resource Management action planner behavior changes.

## Changes

- Removed `localCallers[0]` and `mcpTargets[0]` as fallback sources for permission-change handoff.
- Target resources still prefill themselves as the target when present.
- Caller resources still prefill themselves as the caller when present.
- Missing same-scope partners now remain unset so the permission-change workflow can show its existing completion guard.
- Added regression coverage for missing same-scope caller and missing same-scope target cases.

## Notes

This is a production safety fix for the multi-tenant journey. The user-facing behavior is intentionally conservative: AgentHarbor should ask for missing scope-local resources instead of guessing across tenant boundaries.
