# 0.2.0 Resource Inventory Scope

Date: 2026-06-17
Branch: `codex/resource-inventory-scope`

## Objective

Make the Resource Management main inventory match the active tenant and workspace context. Operators should not see resources, grant counts, route counts, or runtime decisions from another tenant as part of the current workspace.

## 中文说明

上一轮先修复了“准备度缺口”按当前租户和工作区计算的问题。本轮继续把资源管理主视图收束到同一个范围：列表、指标、授权计数、路由计数和运行计数都跟随当前管理上下文，避免管理员在当前租户里看到其他租户的资源或状态。

## Scope

- No backend changes.
- No database or API contract changes.
- No new dependencies.
- Resource Management remains a scoped operational workspace, not a global asset catalog.

## Changes

- `buildResourceLifecycleSummary` now builds all resource lifecycle items first, then publishes only the items matching the active `ManagementScope`.
- Tenant entitlements are counted only when their tenant matches the active scope.
- Workspace assignments, instance assignments, route policies, and runtime traces are counted only when their tenant and workspace match the active scope.
- Setup-gap readiness continues to run against the scoped inventory, so the first operator action and the visible resource list now agree.
- Added regression coverage for cross-tenant resources and historical records that previously polluted the current workspace summary.
- Added a structure guard to keep future resource lifecycle changes wired through scoped inventory helpers.

## Notes

This change intentionally does not add a global asset inventory toggle. The product default remains the operator's current tenant and workspace because this is the safest default for multi-tenant permission operations.
