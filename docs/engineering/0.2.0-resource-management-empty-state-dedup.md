# 0.2.0 Resource Management Empty State Deduplication

Date: 2026-06-17

## Objective

Reduce duplicate first-run empty states in Resource Management. When no resources exist, the page should keep the operation entry and the concrete Agent registry empty state, instead of showing a second generic "no managed resources" card above it.

## 中文说明

本次增量继续收束资源管理页的空系统体验：尚未注册 Agent 或 MCP 资源时，资源状态区不再额外渲染一张“暂无受管资源”空卡。用户只需要看到资源操作入口和下方 Agent 注册表空态，避免首屏出现两个相似的“暂无”提示。

## Scope

- Frontend-only change.
- No backend API contract change.
- No resource summary or non-empty resource list behavior change.
- Existing Agent registry empty state remains the concrete setup guide.

## Changes

- `ResourceLifecycleView` now renders the resource list only when there are resource rows.
- Removed unused empty-list styling for `.resource-lifecycle-empty` and `.resource-lifecycle-list.is-empty`.
- Updated the style regression test to prevent the duplicate empty card from returning.

## Verification

- `node --test frontend/tests/styleTheme.test.mjs`: passed, 34/34.
- Browser DOM check on `http://127.0.0.1:5317/#registry`:
  - Resource command center remained visible.
  - Visible Chinese page text did not include `证据`.
  - The running local stack currently had resources loaded, so the empty-resource branch was verified by regression test rather than by mutating browser data.

## Notes

- This intentionally leaves the concrete Agent registry empty state in place. It is the actionable setup guide for a first-run operator, while the resource lifecycle header already provides the broader process context.
