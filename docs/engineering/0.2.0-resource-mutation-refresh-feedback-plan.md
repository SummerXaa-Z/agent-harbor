# AgentHarbor 0.2.0 Resource Mutation Refresh Feedback Plan

## Goal

Make resource lifecycle operations production-safe after a successful mutation: the console must not misreport a created or changed resource as failed only because the follow-up refresh failed, and the resource lifecycle page must show whether the current resource state is fresh.

## Design Consensus

- Treat the management mutation and the post-mutation refresh as two separate outcomes.
- Keep one-time key material visible even if the follow-up refresh fails.
- Show a compact freshness line in the resource lifecycle command area so administrators know whether they are acting on refreshed data.
- Do not change backend contracts for this increment; this is a console correctness and UX hardening change over the existing management APIs.
