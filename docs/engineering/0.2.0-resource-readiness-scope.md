# 0.2.0 Resource Readiness Scope

Date: 2026-06-17
Branch: `codex/resource-readiness-scope`

## Objective

Make Resource Management readiness gaps respect the active tenant and workspace scope. A caller or target registered in another tenant must not make the current scope appear ready for access-query setup.

## 中文说明

资源管理页之前按全局资源判断“访问查询准备度”。在多租户场景下，这会造成误导：其他租户已经有调用方或目标服务时，当前租户/工作区可能不再提示缺口。本轮把准备度缺口改成按当前 scope 计算，避免跨租户上下文污染。

## Scope

- No backend changes.
- No visual layout changes.
- Keep resource list and metrics unchanged for this increment.
- Only scope the setup-gap readiness calculation.

## Changes

- `ResourceLifecycleInput` now accepts an optional `scope`.
- `resourceSetupGaps` filters caller and target readiness by `tenantId` and `workspaceId` when a scope is provided.
- `ConsoleController` passes the current normalized management scope into `buildResourceLifecycleSummary`.
- Added a regression test proving resources in another tenant/workspace do not satisfy the current scope readiness gaps.
- Added a structure guard to keep the controller wired to scoped readiness.
