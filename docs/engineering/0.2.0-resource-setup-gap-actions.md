# 0.2.0 Resource Setup Gap Actions

Date: 2026-06-17
Branch: `codex/resource-gap-create-agent-action`

## Objective

Close the operator journey break after Capability Governance blocks grant creation because no caller Agent exists. When the operator follows the Resource Management path, the missing caller or target Agent gap must provide a direct, same-page Create Agent action instead of a passive instruction.

## 中文说明

当“创建授权链”因为缺少调用方 Agent 被阻断时，管理员会进入资源管理补齐配置。资源管理页之前只提示“使用上方创建 Agent”，用户仍需要自己寻找入口。本轮改为在“访问查询准备度”缺口中直接提供“创建 Agent”动作，点击后打开现有创建 Agent 弹窗。

## Scope

- No backend changes.
- No new dependencies.
- Reuse the existing Resource Management action modal and mutation flow.
- Keep English and Simplified Chinese copy paired.
- Add structural regression coverage for the actionable setup gap.

## Changes

- `ResourceLifecycleView` accepts `onCreateAgent` and renders caller/target setup gaps as real buttons when the callback is available.
- `ConsoleController` includes `create_agent` in the resource action modal request and wires the setup gap callback to the existing Create Agent dialog.
- The Create Agent action now has a stable `agent-create-panel` id and supports programmatic opening through `openToken`.
- Setup gap copy changed from “Use the Create Agent button / 使用上方创建 Agent” to “Create Agent / 创建 Agent”.
- Button styling resets native button defaults, preserves compact card alignment, and adds a focus-visible ring.

## Notes

This keeps the resource setup path consistent with the production journey principle: every blocked state should expose the next safe action in place, without asking the operator to infer where to go next.
