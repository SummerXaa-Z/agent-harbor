# 0.2.0 Reviewer Approval Queue Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a production-usable Reviewer queue in the AI Admin web console so security reviewers can fetch, inspect, approve, and reject only the permission package approval requests routed to their reviewer identity.

**Architecture:** Reuse the existing permission-package approval API and the backend `reviewer` routing parameter. The frontend stores a reviewer identity, fetches pending requests with `reviewer=...`, renders a compact queue next to the current draft approval evidence, and passes the same reviewer into approve/reject writes. No identity provider, reviewer-rule editor, or storage change is included in this slice.

**Tech Stack:** React + TypeScript frontend, existing API client, existing Node test runner, i18n dictionaries, README/product docs/changelog.
