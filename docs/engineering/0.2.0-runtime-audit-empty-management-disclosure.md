# 0.2.0 Runtime Audit Empty Management Disclosure

Date: 2026-06-17

## Objective

Reduce duplicate empty states on the Runtime Audit workspace. Operators should first see runtime records; an empty Management Audit section should stay available but not compete with the main runtime task.

## 中文说明

本次增量处理运行审计页的空系统体验：当没有管理审计事件时，管理审计区默认收进一个紧凑展开项，不再与“暂无运行记录”并列铺出第二张空态卡。一旦已有管理审计事件，页面仍直接展示管理审计表格，方便追溯。

## Scope

- Frontend-only change.
- No backend API contract change.
- No audit event model, filtering behavior, or non-empty Management Audit table behavior change.
- Applies only to the Runtime Audit workspace; other workspaces keep their existing Management Audit placement.

## Changes

- `TracesView` now receives `managementAuditEventCount`.
- Empty Management Audit on the Runtime Audit page is hidden behind a `details` disclosure.
- Non-empty Management Audit still renders as the normal panel and table.
- Added regression coverage for the disclosure branch and styling.

## Verification

- `node --test frontend/tests/styleTheme.test.mjs`: passed, 35/35.
- Browser DOM check on `http://127.0.0.1:5317/#traces`:
  - The running local stack had management audit events, so the non-empty branch rendered `.audit-table` directly.
  - `.trace-audit-disclosure` was not rendered in the non-empty branch.
  - Visible Chinese page text did not include `证据`.

## Notes

- The empty branch is locked by regression test because the current browser stack contains audit events. Avoiding local data mutation keeps this verification non-destructive.
