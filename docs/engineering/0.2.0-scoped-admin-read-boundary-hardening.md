# 0.2.0 Scoped Admin Read Boundary Hardening

Date: 2026-06-26
Branch: `codex/scoped-admin-read-boundary-hardening`

## Objective

Close scoped administrator read-path metadata leaks across direct object reads, access profiles, access-decision explanations, and permission-package grant creation.

## 中文说明

范围化管理员的写操作和列表查询已经有租户/工作区边界，但部分按 ID 读取和聚合说明路径仍会在知道对象 ID 时返回范围外元数据。对生产环境来说，这会破坏租户隔离，也会让 AI Admin 通过 Management MCP 得到不该看到的 Agent 名称、能力 key 或访问画像。

本轮把读路径和授权创建路径收束为同一条规则：只要返回真实对象、聚合说明或创建授权链，就必须先确认对象落在认证管理员的租户/工作区边界内。`access-profile` 还会把 scoped admin 的有效工作区写回查询，避免省略 `workspaceId` 时读取整租户。

## Scope

- `GET /api/v1/tenants/{id}` tenant detail read.
- `GET /api/v1/agents/{id}` Agent detail read.
- `GET /api/v1/tenants/{id}/access-profile` tenant access profile read.
- `GET /api/v1/access-decisions:explain` HTTP access decision explanation.
- `explain_access_decision` and `get_tenant_access_profile` management MCP tools through shared helpers.
- Permission-package draft/preflight/apply/approval/workbench resource-scope checks for caller and target.
- Manual tenant-entitlement creation resource-scope checks for target and capability.
- Workspace-assignment and instance-assignment creation checks for existing entitlement, assignment, target, and capability scope.
- Access-grant list filtering for cross-scope caller/target relations.
- Data-plane legacy access-grant enforcement for cross-scope caller/target relations.
- Access-grant revoke lookup for scoped administrators.
- Runtime trace list filtering for cross-scope caller/target relations.
- Permission-package production readiness and report query scope checks for caller and target resources.
- Scoped access-profile object hydration for stale or dirty target/capability references.
- Permission-package application impact and health capability hydration for stale or dirty capability references.
- `make release-check` browser-facing AI Admin journey gate.
- Focused HTTP API tests.
- Changelog, README, and release checklist.

## Changes

- Added scope checks before tenant and Agent detail responses.
- Added request-aware access-profile builder that applies the authenticated admin's effective workspace boundary.
- Prevented workspace-scoped access-profile reads from returning grants without matching workspace assignments.
- Added pre-evaluation resource-scope checks for access decision explanations, covering caller, target, and capability IDs before evidence messages are generated.
- Added permission-package resource-scope checks so scoped administrators cannot use an in-scope tenant/workspace request to grant an out-of-scope target or capability.
- Added assignment resource-scope checks so scoped administrators cannot attach existing out-of-scope tenant entitlements or inspect out-of-scope workspace assignments before authorization.
- Tightened access-grant list filtering so scoped administrators only see grants whose caller and target are both inside the effective management scope.
- Tightened access-grant fallback enforcement so historical or imported grants cannot authorize data-plane calls between agents outside the same tenant workspace.
- Tightened access-grant revoke handling so scoped administrators only find and revoke grants visible in their effective management scope, returning not found for cross-scope relations.
- Tightened runtime trace list filtering so raw route traces require both caller and target agents to be inside the effective management scope, while tenant-governed capability traces must match the scoped tenant/workspace, caller instance, and authorization records.
- Reused permission-package resource-scope checks for production readiness and report queries so an in-scope tenant/workspace cannot be paired with an out-of-scope caller or target to expand draft, profile, runtime, or application metadata.
- Tightened access-profile hydration so stale or dirty grant rows can keep their grant-chain record but no longer expand out-of-scope Agent names or capability keys.
- Tightened permission-package application impact and health hydration so stale or dirty application rows only expose capability keys that still belong to the recorded application target.
- Added the browser-facing AI Admin journey to `make release-check`, including isolated default ports and bounded cleanup so the gate does not collide with local demo services or hang after success.
- Added regression tests proving out-of-scope metadata is not returned by REST or management MCP paths.
