# 0.2.0 Secure Console Session Cookie

Date: 2026-06-23
Branch: `codex/production-secure-session-cookie`

## Objective

Make web-console session cookies production-safe behind a TLS-terminating reverse proxy without trusting spoofed forwarded scheme headers from direct public clients.

## 中文说明

Web 控制台登录后会把管理员密钥换成 `agent_harbor_session` Cookie。生产部署常见形态是浏览器到网关走 HTTPS，而网关到 AgentHarbor 进程走 HTTP。如果服务端完全不识别可信反代的 HTTPS 信息，Cookie 会缺少 `Secure`；如果无条件信任 `X-Forwarded-Proto`，公网客户端又可以伪造请求头影响安全属性。本轮把这条边界收窄为：真实 TLS 请求直接设置 `Secure`；只有请求来源是本机或私网代理时，才读取 `X-Forwarded-Proto: https` 或 `Forwarded: proto=https`。

## Scope

- Backend console session cookie security attributes.
- Trusted forwarded scheme parsing for loopback/private proxy sources.
- Regression tests for direct TLS, trusted forwarded HTTPS, RFC `Forwarded`, and untrusted spoofing.
- Production hardening scenario coverage for trusted HTTPS-forwarded console login.
- README and changelog updates.
- No frontend, API contract, storage, or dependency changes.

## Changes

- `consoleSessionCookie` still sets `HttpOnly` and `SameSite=Lax`.
- `Secure` is now set when:
  - the request is direct TLS; or
  - the request source is loopback/private and `X-Forwarded-Proto` resolves to `https`; or
  - the request source is loopback/private and `Forwarded` includes `proto=https`.
- Public or otherwise untrusted remote clients cannot force `Secure` by spoofing `X-Forwarded-Proto`.
- `make production-hardening` now performs a trusted forwarded console login and asserts the response `Set-Cookie` contains `Secure`.
