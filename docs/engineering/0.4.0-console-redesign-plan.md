## 1. 盘点结论：附录 A 需要修正的地方

附录 A 的"大部分直连"成立，但下列事实会改变原型的假设：

| # | 发现 | 位置 | 对重设计的影响 | 处理 |
| --- | --- | --- | --- | --- |
| F1 | 审计列表返回**最旧** N 条（memory `rows[:limit]`；postgres `order by created_at asc … limit n`），默认 limit 100 | `internal/store/memory.go:1365`、`internal/store/postgres.go:2171` | 驾驶舱"最近审计"、通知、今日计数都会拿到旧数据（即已知的"审计表停在最早 10 条"） | P0：改为最新 N 条、响应仍升序（对齐 `ListTraces`） |
| F2 | `audit/traces` 不设 limit，返回全部 | `internal/httpapi/server.go:6533` | 数据增长后拖慢驾驶舱与审计页 | P0：可选 `limit`、`since`、`until` |
| F3 | `metrics/runtime` 只有总量 | `server.go` runtimeMetrics | 趋势图没有数据源；前端分桶截断列表会失真 | P0：日聚合端点 |
| F4 | 浏览器只能探测 `<origin>/healthz`，只拿得到 `HTTP nnn` 或 "Failed to fetch"；后端 `classifyUpstreamError` 只在能力刷新里用，而刷新会写能力与审计 | `server.go:6465`、`server.go:7529` | §0.2 要求动态显示连接拒绝 / DNS / TLS 根因 | P0：只读探测端点 |
| F5 | 策略闸门对低风险只读包给出 `canApplyDirectly=true`；此时创建审批返回 400 `permission package does not require approval` | `internal/permissionpack/permissionpack.go` buildPolicyGate；`server.go:7167` | 原型"所有变更必须审批"不成立 | 状态机增加"无需审批"态 |
| F6 | 交接令牌 TTL 默认 1800s、最大 3600s | `internal/httpapi/access_handoff.go` | 原型有效期 1 小时 / 24 小时 / 7 天不可行 | 选项改为 15 / 30（默认）/ 60 分钟 |
| F7 | 创建令牌响应含一次性明文 `key`；旧版面板直接渲染 | `frontend/src/components/AccessHandoffPanel.tsx:270` | 与 §6 红线冲突 | 见 D4；新版护栏测试禁止渲染 |
| F8 | 工作区不是实体（由 agent `workspaceId` 与分配派生）；模板是静态只读目录；路由规则只按 caller / target / routeType / routeKey 匹配 | `tenantOrganization.ts`、`permissionPackages.ts`、`RoutePolicy` | 原型的"新建工作区""编辑/新建策略""subject = …"匹配没有后端 | 见 §13 差异清单 |
| F9 | 审批列表没有 `requestedBy` 过滤；审批人规则（`AGENT_HARBOR_APPROVAL_REVIEWERS`）不经 API 暴露 | `server.go` 审批列表 | "我的申请"需前端按 `requestedBy` 过滤；审批人选择器无法列出规则 | 演示期可接受，列入后续 |
| F10 | 前端缺 3 个 client：applications 列表、api-keys 列表、route-policy PATCH（后端都已有） | `frontend/src/api.ts` | 我的资源 / 我的权限 / 路由开关需要 | P1 补齐 |
| F11 | 旧版 `:root` 与原型 token 同名冲突（`--bg`、`--danger`、`--radius`、`--success` 等），且有 `*`、`body`、`button`、`table`、`td` 等全局选择器；`styleTheme.test` 锁定旧 token | `frontend/src/styles.css` | 直接套用会互相污染 | 新样式全部挂 `.ah2`；旧版样式改为随旧版 chunk 加载 |
| F12 | `App.tsx` 被护栏锁定（≤20 行，必须 `return <ConsoleController />`）；`main.tsx` 不受约束 | `frontend/tests/styleTheme.test.mjs` | 不能在 App.tsx 里分流 | 在 `main.tsx` 挂 `RootEntry` |

## 2. 技术栈与挂载方式

- **依赖**：复用 React / Vite / TS / lucide-react；不引入路由库、UI 库或图表库。hash 路由为纯模块 `router.ts`；趋势图与环形图手写 SVG。
- **挂载**：
  - `main.tsx` 改为渲染 `RootEntry`。
  - `RootEntry` 监听 `hashchange`，按 `router.ts` 的判定懒加载 `redesign/RedesignApp` 或 `LegacyEntry`。
  - `LegacyEntry` 负责 `import "./styles.css"` 并渲染 `<App />`，让旧版全局样式只随旧版 chunk 加载。`App.tsx` 不改，护栏保持通过。
- **样式**：
  - 新建 `frontend/src/styles/redesign.css`，`.ah2` 根类内精确声明 §3.1 token，并在 `.ah2` 内重置元素样式。
  - token 块之外只允许 `var(--*)`，不允许裸色值（由测试保证）。
  - 旧版 token 一律不动。
- **i18n**：
  - 新文案进 `i18n.ts` 的 `rd.*` 命名空间，zh/en 成对。
  - 中文与英文的语义以本计划为准；公开评审前复核英文。
  - 复用既有键：`auditAction.*`、`traceReason.*`、`auditSummary.*`、`productionCheck.*`、`permissionPackage.*`、`ask.*`，以及 #391 的 `text.readinessChecks`、`text.journeySteps`、`metric.productionReadyChecks`。
- **数据**：
  - 新增 `useRedesignData` 包装 `loadConsoleData`。`loadedFromApi=false` 时显示"网络错误"横幅与"示例数据"标签，不再静默回退。
  - 原型示例 ID 只在示例数据模式出现。
- **能力探测**：
  - 按 `system/info` 的 capabilities 判断 `metrics_daily_v1`、`target_probe_v1`。
  - 旧后端显示明确的"需要升级后端"空态，不伪造数据。
- **本地预览**：
  - 新增本地 `.claude/launch.json`，包含 API 与 Vite 两个配置，供浏览器预览验证。
  - 若该目录被忽略，则不入库。

## 6. 新增接口契约（P0，单独后端 PR）

### 6.1 日聚合：`GET /api/v1/metrics/daily`

- **参数**：
  - `days`：1–30，默认 7。
  - `tzOffsetMinutes`：-720–840，默认 0。前端传 `-new Date().getTimezoneOffset()`，不依赖 tzdata。
  - `tenantId` / `workspaceId`：管理范围，规则同列表端点。
- **响应**（桶连续且补零，`denyRate` 在 `calls=0` 时为 `null`）：

```json
{
  "code": 0,
  "data": {
    "days": 7,
    "tzOffsetMinutes": 480,
    "from": "2026-09-19",
    "to": "2026-09-25",
    "generatedAt": "2026-09-25T08:00:00Z",
    "truncated": false,
    "totals": { "calls": 84, "allowedCalls": 70, "deniedCalls": 14, "auditEvents": 51 },
    "buckets": [
      { "date": "2026-09-19", "calls": 12, "allowedCalls": 9, "deniedCalls": 3, "denyRate": 0.25, "auditEvents": 8 }
    ]
  }
}
```

- **口径**：
  - `calls` = 窗口内 trace 事件数（每次网关判定一条）。
  - `auditEvents` = 窗口内审计事件数。
  - 两者都经过与列表端点**相同的可见性过滤**（含 `visibleAuditEvents`），保证与列表口径一致。
- **实现**：
  - 按窗口读取行后在 Go 内分桶：trace 单窗口上限 20,000 行，审计事件 5,000 行。
  - 各多取一行判断是否超限；超限时保留最新的行并置 `truncated=true`，因此截断只会让最早几天偏少。
  - 不在前端对截断列表分桶。
- **错误**：参数越界返回 400 `VALIDATION_FAILED`。
- **契约登记**：`systemCapabilities` 增加 `metrics_daily_v1`，同步修改 `server_test.go` 中的能力清单断言。

### 6.2 审计列表"最新 N 条"修复 + 时间窗

- **最新窗口**：
  - 规则：`ListAuditEvents` 带 limit 时返回**最新** N 条，响应仍按时间升序。
  - memory：取尾部切片。
  - postgres：`(… order by created_at desc, id desc limit $n)` 子查询外层再升序，与 `ListTraces` 完全对齐。
- **兼容性**：
  - 既有断言保持通过（升序、`limit=1` 返回 1 条）。
  - readiness 内部调用（`server.go:2704`，单个应用 ID、limit 1）改为取最新一条，语义更准确。
  - CHANGELOG 记入 Fixed。
- **时间窗**：
  - `audit/events` 与 `audit/traces` 增加 `since` / `until`（RFC3339，含 since、不含 until），非法值返回 400。
  - `audit/traces` 增加可选 `limit`（1–500），缺省保持现状（不限）。
- **已知取舍**：可见性过滤发生在 limit 之后，可能少于 N 条，这是现状行为，文档注明。

### 6.3 只读探测：`POST /api/v1/targets/{targetId}:probe`

- **行为**：
  - 与能力发现发送相同的 `tools/list` 请求，共用同一请求构造函数和认证头。
  - **不写能力、不写审计**；超时 5s。
  - 只探测已登记目标的端点，不接受任意 URL，没有 SSRF 面扩张。
  - 需要管理权限，POST 带 CSRF。
- **响应**：目标存在时一律 200，探测失败作为数据返回，不作为 HTTP 错误。

```json
{
  "code": 0,
  "data": {
    "targetId": "agt_9cb77de5…86384",
    "endpoint": "http://127.0.0.1:18787/mcp",
    "status": "error",
    "errorCode": "UPSTREAM_CONNECT_ERROR",
    "message": "connection refused",
    "httpStatus": 0,
    "toolCount": 0,
    "durationMs": 12,
    "checkedAt": "2026-09-25T08:00:00Z"
  }
}
```

- **取值**：
  - `errorCode` ∈ `UPSTREAM_CONNECT_ERROR | UPSTREAM_DNS_ERROR | UPSTREAM_TLS_ERROR | UPSTREAM_TIMEOUT | UPSTREAM_ERROR`，前端经既有 `upstreamErrorCodeKeys` 本地化。
  - `message` 不含凭据。
- **错误**：
  - 目标不存在返回 404，越权返回 403。
  - 非 MCP 目标、缺端点、`headers` / `credentialHeaders` / `timeoutMs` 配置非法返回 400 `VALIDATION_FAILED`。这些是智能体记录的配置问题，不作为探测结果。
- **实现细节**：
  - `endpoint` 去掉 URL 中的 userinfo；传输错误先剥掉请求 URL 再分类，`message` 不会带出 userinfo。
  - `httpStatus` 始终输出，没有收到响应时为 `0`。
- **契约登记**：`systemCapabilities` 增加 `target_probe_v1`。

## 10. 视觉、交互与可访问性落地

- **Token**：精确使用 §3.1 token。

  - 列宽在 `tableColumns.ts` 声明，合计 100%。
  - 关键信息不截断；截断时必须带 title 或详情链接。

  - ≤1100px：两列网格。

- **可访问性**：
  - 全部可键盘到达。
  - ⌘K 支持方向键、Enter、Esc。
  - Modal 焦点陷阱，Esc 关闭。
  - Toast 使用 `aria-live`。
  - 状态始终"图标 + 形状 + 文字"，不单靠颜色。
- **错误分类**：
  - `apiErrorCategory` 分四类：网络错误（fetch 失败）、无权限（401/403）、资源不存在（404）、服务不可达（502/503/504 与 `UPSTREAM_*`）。每类附下一步建议。

## 15. 风险与缓解

- **范围大**（14 页 + 壳 + 横切能力）：严格按期交付；每期都保持可演示、可回退（旧版始终可用）。
- **共存期双份维护**：业务判定只在共享纯函数模块中保留一份；旧版只修阻断级问题。
- **演示身份模型**：所有申请人都是 `local-dev`，"我的"语义停留在演示级别；在界面与差异清单中明示，真实身份随登录生效。
- **轮询开销**：15s 周期、页面隐藏暂停、审批列表 limit 100；P0 之后审计与 trace 都有 limit 和时间窗。
- **审计窗口修复是行为变化**：API 消费者如果依赖"最旧 N 条"会受影响（可能性低）；CHANGELOG 记入 Fixed，响应顺序不变。
- **探测端点**：只探测已登记端点，需要管理权限，不写状态；与现有"刷新能力"的攻击面一致。
