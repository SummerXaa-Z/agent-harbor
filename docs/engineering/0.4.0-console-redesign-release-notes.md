# AgentHarbor v0.4.0 Release Notes

Status: release-ready. Target tag: `v0.4.0`.

v0.4.0 replaces the web console with the redesigned dual-surface console and completes the permission-change journey end to end: runtime validation without a bootstrap token, re-submission after apply, honest routing for unknown routes and deep links, and state visibility in the admin lists. It also rounds out the observability surface (daily decision metrics, target probing, bounded audit windows, self access-profile) and documents the deployment boundary the gateway depends on.

## Highlights

- **Redesigned console (the only console).** The empty hash opens an entry page choosing between the user workbench (permission apply, access query, go-live check, my records) and the admin console (cockpit, approvals, capability governance, resource registry, tenants, access policies, route rules, runtime audit, administrators). A ⌘K / Ctrl+K command palette reaches every page, high-frequency actions, and recently updated agents and approval requests; a notification center derives pending approvals, approval outcomes, and environment-check failures from live APIs. The layout collapses below 860px. The pre-0.4.0 console is retired: old bookmarks redirect to their redesign successors, and unrecognized hashes land on a not-found page that keeps the attempted path.
- **Runtime validation without a bootstrap deadlock.** When the runtime-records check blocks go-live, the console offers a controlled run that creates a temporary agent key, issues one allowed and one denied governed call for the applied package's probes, and revokes the key immediately after — so proving runtime behavior no longer requires a token before the token's own package is live.
- **Re-submission after apply.** Editing an applied package's snapshot fields (region, request text, subject selector, requested capability) detaches the consumed approval and falls back to the normal submit flow, so changes raise a fresh approval instead of a dead "needs approval" state. The approval's scope now covers the full request snapshot, matching the backend's attachment rule.
- **Data-domain governance made legible.** Capabilities blocked only because they have no data-domain classification render separately from by-design template blocks, with notices on both the permission preview and capability governance. Classification stays mandatory — nothing is auto-assigned.
- **Observability.** `GET /api/v1/metrics/daily` counts gateway decisions and audit events per local day (advertised as `metrics_daily_v1`); `POST /api/v1/targets/{targetId}:probe` checks a registered MCP target without writing capabilities or audit events (`target_probe_v1`); audit events and traces accept RFC3339 `since`/`until` bounds (traces also a bounded `limit`); `GET /api/v1/self/access-profile` gives any agent key a read-only view of its own effective boundary, bounded by Access Handoff bindings.
- **Honest MCP lifecycle.** Governed MCP routes answer `initialize`, `ping`, and `notifications/*` locally so standards-compliant clients can connect; `tools/list` stays filtered to authorized capabilities, and explicit route-policy decisions keep precedence.
- **Security.** `SECURITY.md` documents the deployment boundary (an MCP upstream must only be reachable from the gateway network) with verification steps. Data-plane auth failures now distinguish revoked from expired keys for stored keys while guessed tokens keep the generic message. Token values stay masked everywhere in the console.

## Console compatibility contract

- Old bare hashes redirect to their redesign successors: `#ask` → `#user/ask`, `#access` → `#user/mine`, `#getting-started` → `#user/home`, `#go-live`/`#evidence` → `#user/golive`, `#ai-admin` → `#admin/approvals`, `#admin-access` → `#admin/admin`, and the other legacy nav keys (`#cockpit`, `#traces`, `#tenants`, `#registry`, `#capabilities`, `#policies`, `#routes`). The slash alias `#/ask` works the same way.
- Bare hashes with no redesign successor (for example `#users`) land on the not-found page with the attempted hash kept in the address bar.
- Slash-shaped hashes that match no view (`#/user/applyx`, `#/nonsense`) also render the not-found page instead of silently resetting to a surface home.
- The pre-0.4.0 console's API integrations live on in shared modules; no backend endpoints were removed with it. The 0.3.x report-export compatibility aliases remain available for old clients.

## Upgrade and rollback

- No new database migrations since 0.3.0 (latest remains `015_permission_package_requested_capability.sql`): upgrading is replacing the server binary and the frontend build, then restarting.
- Configuration is unchanged; no new required environment variables.
- Rollback to 0.3.x is a binary/frontend swap in the other direction. Data written by 0.4.0 (audit events, approval snapshots; metrics are derived, not stored) remains readable by 0.3.x schemas. The console difference is purely client-side: bare legacy hashes work natively again in 0.3.x, while `#user/*` / `#admin/*` hashes are 0.4.0-only.
