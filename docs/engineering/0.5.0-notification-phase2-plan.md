# 通知第二期计划（0.5.0：令牌生命周期 + 环境通知时效性）

状态：已定稿，2026-10-01 开工。承接 `0.4.0-console-redesign-plan.md` §8 的第二期条目
与第五轮外部评估 #40 的 triage 结论。

## 背景与调研结论

一期通知（0.4.0 P5）全部前端派生：15s 轮询审批列表 + 订阅环境检查快照，dedupe
`${kind}:${resourceId}:${status}`，已读状态存 localStorage 跨标签页同步。计划文档把
"目标不可达、令牌过期的主动推送"留到二期并注明"需要后端事件源"。2026-10-01 的代码调研
（v0.4.1，ee84604）确认：

- 后端无任何后台任务（唯一 goroutine 是 `ListenAndServe`），令牌过期是惰性判定
  （读时计算 `expiresAt`/`revokedAt`），没有任何代码路径写过期事件；探测端点
  `targets/{id}:probe` 按设计**不写任何持久状态**。
- HTTP 层有双超时（chi `Timeout(30s)` + server `WriteTimeout: 35s`），SSE/长轮询需要
  绕开两者；存储层无 pub/sub。
- 令牌的撤销/过期状态在现有列表 API（`GET /api/v1/api-keys`）里就完整可见（prefix、
  `expiresAt`、`revokedAt`）；撤销另有事务性审计事件 `access_handoff.token_revoked`。
- #40 根因：两条结构性空态通知（未注册目标 `rd.envcheck.mcp.noTarget`、无申请记录
  `rd.envcheck.corePath.noApp`）派生自模块级环境检查快照缓存，只有某个面跑检查时才
  刷新，条件解除后以未读常驻。

## 目标（本期交付）

1. **令牌生命周期通知（用户侧）**：交接令牌（`createdForHandoffId` 存在）过期或撤销时，
   通知中心出现"交接令牌已过期 / 已撤销"，副行显示掩码前缀，时间取
   `revokedAt ?? expiresAt`，点击深链 `#user/golive`。新 kind `token`。
2. **#40 修复（管理侧）**：两条结构性空态通知改由实时数据派生——"未注册 MCP 目标"看
   注册目标数（agents 里 `channelType === "mcp"` 且带 endpoint），"无申请记录"看权限包
   应用数——数据随通知轮询刷新，条件解除后通知立即从派生列表消失（未读随之清零），
   不再依赖环境检查快照、无需手动"全部标记已读"。探测依赖的行（API 错误、上游不可达、
   健康告警）维持快照派生不变。

## 非目标（及理由）

- **服务端主动推送 / SSE / WebSocket**：双超时与无 pub/sub 存储决定了"推送"实为轮询；
  现有 15s 轮询已覆盖时效性。真正的服务端事件流留待有真实多客户端需求时再评估。
- **服务端周期性探测目标可达性**：需要引入无先例的后台定时器、为探测结果新增持久化，
  且违反 `:probe` 端点"只读、不写审计"的既定契约。"目标不可达"继续由环境检查快照
  派生（任一面跑检查即刷新）。
- **令牌"即将过期"预警**：交接令牌 TTL 上限 3600s、默认 1800s，"即将"是分钟级且必然
  发生，预警只有噪音；计划 §8 的原始条目也只列"已过期 / 已撤销"。
- **令牌过期的后端审计事件**：过期由读取方惰性判定是既定设计；为通知去改写认证路径
  得不偿失。列表派生已覆盖。
- **"我的令牌"按持有者过滤**：与"我的申请"一样属演示身份语义（已知未修 #16 家族），
  本期沿用 management 范围列表 + 仅交接令牌过滤。

## 设计

### 派生（frontend/src/redesign/model/notifications.ts）

- `NotificationKind` 增加 `"token"`；`NotificationDeriveInput` 增加可选字段
  `now?: number`、`keys?: readonly AgentKey[]`、
  `structuralEnv?: { registeredTargetCount: number; applicationCount: number } | null`
  （缺省保持一期行为，旧调用与测试不受影响）。
- 令牌分支：遍历 `keys`，仅取 `createdForHandoffId` 非空的交接令牌，用
  `keyStatus(key, now)`（`userWorkbench.ts`，`revokedAt` 优先）判定；`expired`/`revoked`
  产出用户侧条目：dedupe `token:{keyId}:{status}`，`createdAt = revokedAt ?? expiresAt`
  （面板因此显示时间），副行 `params.prefix = maskSecret(key.prefix)`（掩码红线）。
- 结构性环境分支：`structuralEnv` 提供时，环境行派生跳过 `rd.envcheck.mcp.noTarget` 与
  `rd.envcheck.corePath.noApp` 两行，改由计数派生——目标数为 0 产出
  `env:mcp:warning`（副行沿用 `rd.envcheck.mcp.noTarget`，与旧 dedupe 一致以继承已读
  状态），应用数为 0 产出 `env:corePath:warning`。其余环境行（error/warning）不变。
- 已读基线规则不变：`token` 条目在 `createdAt` 早于基线时自动视为已读（新浏览器不回放
  历史死令牌），env 与 pending 永不自动已读。

### 轮询（frontend/src/redesign/hooks/useNotifications.ts）

15s 轮询从单一审批列表扩展为四路并行（各路独立吞错，受限会话只丢对应来源）：
approvals(limit 100，现状)、agents、api-keys、permission-package applications(limit 5)。
派生输入：agents 现由轮询新鲜数据供给（`registeredMcpTargets()` 计数，谓词复用
`envChecks.ts`），应用数取 applications 长度。页面隐藏暂停、恢复即拉、run-id 防串染
等既有行为不变。

### 文案（frontend/src/i18n.ts，en + zh 双语）

`rd.nt.kind.token`、`rd.nt.token.expired.title`、`rd.nt.token.revoked.title`、
`rd.nt.token.sub`（`{prefix}`）。面板渲染完全复用现有通用行，无需改 NotificationCenter。

  自动消失且未读清零；控制台无报错、界面无未掩码令牌。
