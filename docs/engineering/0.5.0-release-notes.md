# AgentHarbor v0.5.0 Release Notes

Status: released 2026-10-01. Minor release on top of v0.4.1: notification
phase 2 (handoff-token lifecycle plus live structural environment rows) and a
security dependency bump. No schema changes, no new migrations, no API
contract changes — the release is frontend-only plus one dev-workspace
dependency override.

## Highlights

- Handoff-token lifecycle notifications (PR #408). An Access Handoff token
  that has expired or been revoked now raises a user-side notification: the
  title names the transition, the sub line carries the masked prefix
  (12 characters plus ellipsis, never the plaintext), the timestamp is the
  revocation or expiry time, and the item deep-links to the go-live page.
  Active and non-handoff keys stay out; tokens that predate a browser's
  notification baseline count as read, so a new browser does not replay
  long-dead tokens.
- Structural empty-state environment notifications follow live data (round 5,
  finding #40, PR #408). The "no registered MCP target" and "no permission
  applications" warnings derive from live counts refreshed on the 15-second
  poll instead of the environment-check snapshot, so they clear the moment
  the condition resolves instead of lingering unread. Dedupe ids and copy are
  unchanged, so read state carries over. Probe-dependent rows (an unreachable
  target) stay snapshot-derived by design.
- The notification poll fetches its four sources (approval requests, agents,
  agent keys, applications) in parallel with per-source failure isolation —
  a forbidden or unreachable endpoint no longer starves the other sources.
- Security dependency bump (PR #409): hono override in `scripts/real-mcp`
  4.13.5 → 4.13.12, clearing npm advisory GHSA-hxh3-vqpv-xpqv (moderate XSS
  in hono <4.13.7, reachable through `@modelcontextprotocol/sdk`).

## Compatibility notes

- No migrations (still 015, unchanged since v0.4.0); upgrading is a binary
  swap, and rollback is the previous binary.
- No API contract changes; no backend changes at all in #408.
- Notification read state (`agent-harbor-notifications-v1` in localStorage)
  keeps working across the upgrade: existing env-warning ids are reused, and
  token items integrate with the same baseline/read rules.
- Documented non-goals (see `docs/engineering/0.5.0-notification-phase2-plan.md`):
  server push/SSE for notifications, server-side periodic probing,
  expiring-soon warnings (token TTL is capped at 3600s), token-expiry audit
  events, and per-holder token filtering.

## Verification

- Frontend tests 262/262 (two new cases: token lifecycle covers handoff keys
  only with masked prefixes and correct transition times; structural
  empty-state rows follow live counts with read-state continuity);
  `make check`, `make release-check`, and `make evaluation-readiness` green
  on the tagged tree.
- PR CI 6/6 on #408 and #409; main CI green on both merge commits
  (665e192, 842a52d).
- Browser end-to-end on the preview stack: a token issued and revoked through
  the go-live UI raises「交接令牌已撤销」with masked prefix and correct time;
  an API-issued 1-second-TTL token raises「交接令牌已过期」, sorted newest
  first; the admin surface shows no structural empty-state warnings while
  live targets and applications exist; Simplified Chinese and English copy
  both render; no token plaintext appears anywhere; zero console warnings.
