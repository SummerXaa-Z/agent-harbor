# AgentHarbor v0.5.3 Release Notes

Status: released 2026-10-01. Patch release on top of v0.5.2: auditable
access-handoff config interactions (external evaluation round 3, finding 6,
PR #417). No schema changes, no migrations; the API addition is purely
additive.

## Highlights

- Access-handoff config preview and copy actions are now auditable (finding
  6, PR #417). Previewing or copying the handoff configuration is a
  sensitive delivery action, but only token create/revoke events existed
  before. The go-live handoff card now reports each interaction to the new
  `POST /api/v1/permission-packages/access-handoff/events` endpoint, which
  appends `access_handoff.config_viewed` / `access_handoff.config_copied`
  audit events (resourceType `access_handoff`, resourceID = handoff id).
- The endpoint validates the same readiness scope as token creation: 409
  `ACCESS_HANDOFF_NOT_READY` for blocked handoffs, 409
  `ACCESS_HANDOFF_CHANGED` for stale handoff ids, and 400
  `VALIDATION_FAILED` for actions outside the two allowed values. Audit
  metadata carries identifiers only (application, caller, target, template,
  subject selector, artifact name) — the artifacts themselves hold
  placeholders, so no secret reaches the audit trail.
- The console makes the MCP client config preview opt-in again: a
  「预览技术细节 / Preview technical details」 toggle reveals the config, and
  every expand is a deliberate, audited action. Both copy paths — the copy
  button and the code block's copy button — report `config_copied` after a
  successful clipboard write. Reporting is fire-and-forget and never blocks
  or fails the copy. The audit center renders the new actions and resource
  type in Simplified Chinese and English.

## Compatibility notes

- No migrations (still 015, unchanged since v0.4.0); upgrading is a binary
  swap, and rollback is the previous binary.
- API additions only: one new POST endpoint under access-handoff. No
  existing route, contract, or payload changed.

## Verification

- Frontend tests 263/263; `make check`, `make release-check`, and `make
  evaluation-readiness` green on the tagged tree; PostgreSQL integration
  suite green in CI.
- New httpapi test `TestAccessHandoffConfigInteractionsAreAudited`: blocked
  409 before readiness, 400 on unknown action, 409 on stale handoff id,
  both events recorded with resource/metadata assertions, and no
  authorization values in the audit response.
- End-to-end on the preview stack from an empty store: tenants → caller and
  target agents → capability refresh and domain classification → approval →
  apply → runtime validation (4/4 ready), then preview expand and both copy
  paths produced the expected audit rows; the audit center rendered them in
  Simplified Chinese and English with no unexpected console errors.

## Known follow-ups (not blocking)
