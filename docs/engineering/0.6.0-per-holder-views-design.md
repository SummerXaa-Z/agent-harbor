# AgentHarbor 0.6.0 按持有者视图设计说明（#16 族收口）

> 状态：已批准（2026-10-01），按 §11 分期实施中。已选定方案 1（管理员身份绑定
> 调用方 Agent）；待拍板项 A/B/C 均按推荐采纳，其中 B 落地时收紧为**仅 platform**
> （与既有管理员身份管理端点一致，见 §12）。基线 main `85a6ad0`（v0.5.3）。

## 1. 背景与问题

- 「#16 族」指演示身份语义：用户侧「我的申请 / 我的权限 / 我的上线」按**自由切换的接入
  上下文**取数，登录身份与"我是谁的调用方"没有绑定。任何登录的管理身份都能查看其租户
  范围内任意调用方的申请、令牌与交接配置；`security_reviewer` / `platform_admin` 更宽。
- 已存在的地基（本设计的直接依赖）：
  - `internal/httpapi/admin_scope.go`：会话 principal（actor/role/tenantId/workspaceId）、
    `requireRequestedScopeAllowed` 已把 `tenant_admin` 收窄到本租户/工作区；
  - 登录/会话/演示旁路：`developmentAdminBypassActive()`（无管理密钥、无身份、允许未认证
    管理时 `requiresLogin=false`，会话为 `local-dev` platform_admin）；
  - 差异清单 #16 的演示级承诺（申请人统一 `local-dev`、前端按 `requestedBy` 过滤）已交付。
- 用户侧实际取数面（需要收窄的全部入口）：
  - 列表类（全量返回，前端再派生）：`GET /permission-packages/approval-requests`
    （limit 100）、`GET /permission-packages/applications`（limit 20）、`GET /api-keys`；
  - 旅程类（按 caller 过滤但 caller 任意）：drafts / `:preflight` / `:apply` /
    approval-requests POST / production-readiness GET / access-handoff GET /
    access-handoff events + tokens / access-profile（管理变体）——全部经
    `requirePermissionPackageQueryScope → requirePermissionPackageDraftScope`。

## 2. 目标

- 登录会话可以绑定"所持调用方 Agent"；绑定后，该身份在用户侧只能以其持有调用方作为
  caller 查看、申请、交接与签发令牌（服务端强制，前端只做呈现层收窄）。
- 演示模式（`requiresLogin=false`，`local-dev`）行为**完全不变**。
- `platform_admin` 不受影响（管理员视角天然全量）。
- 绑定关系可管理、可审计、改绑即时生效。

## 3. 非目标

- 不引入新角色、不做 SSO/OIDC、不做终端用户（subject）级身份。
- 不采用方案 2（用户侧用 Agent 密钥做会话）：交接令牌 TTL ≤ 3600s，作会话凭据需要长生命
  周期密钥，安全权衡不划算（见会话决策记录）。
- 不改动审批职责分离（自审拦截）与租户级收窄规则；持有者收窄在其上**叠加**。

## 4. 数据模型（迁移 016）

- `admin_identities` 新增 `owned_agent_ids jsonb not null default '[]'::jsonb`
  （id 列表沿用 009/010 的 jsonb 惯例）。存储前去重排序。
- 校验：每个 id 必须是已存在的 Agent，且该 Agent 的租户落在身份自身管理范围内
  （`platform_admin` 不限；`tenant_admin` 限本租户）。不强制 `channelType`，但管理界面
  只列 local 调用方。
- 域模型：`AdminIdentity.OwnedAgentIDs []string`（json `ownedAgentIds`）。
- 反向查询（Agent → 持有者）暂不建索引：身份数量小，鉴权路径按 actor 唯一索引正向查。

## 5. 鉴权与收窄规则

**核心单点**：在 `requirePermissionPackageDraftScope` 的 `CallerInstanceID` 分支追加持有者
检查（一处覆盖 §1 列出的全部旅程类端点）：

```
requireHolderScope(r, callerInstanceID):
  无 principal（演示/旁路）        → 放行
  principal.Role == platform_admin → 放行
  按 actor 查 admin identity（GetAdminIdentityByActor，唯一索引）:
    托管身份不存在或已停用         → 拒绝（403 PermissionDenied）
    bootstrap 身份（配置来源）     → 放行（不可绑定，视为空绑定）
    owned 为空                     → 放行（回退现有租户范围语义，见下）
    callerInstanceID ∈ owned       → 放行；否则 403
```

- **改绑即时生效**：检查按 actor 实时查库（每请求一次、唯一索引命中），不把 owned 集合
  缓存进会话。
- **bootstrap 身份回退**：引导身份（`AGENT_HARBOR_ADMIN_IDENTITIES`）不在存储中、不可绑定，
  按空绑定放行——否则升级即破坏既有租户范围引导管理员。托管身份缺失/停用仍拒绝（停用
  身份的存量会话随之失效，与既有禁用语义一致）。
- **空绑定回退语义（待拍板 A，推荐采纳）**：owned 为空的身份沿用现有租户范围语义。
  理由：升级零破坏（存量 `tenant_admin` 登录不会被锁在用户侧之外），绑定即显式启用
  按持有者收窄；绑定后立即收紧。反方案"空绑定一律拒绝"是最小权限默认，但会把升级变成
  破坏性变更，需要平台管理员先绑定才能用，操作顺序负担大。
- 租户收窄先于持有者检查执行（`tenant_admin` 绑定不了范围外 Agent，双重校验一致）。

**列表收窄**（holder 生效的身份，即 owned 非空且非 platform）：
- approval-requests GET：仅返回 `callerInstanceId ∈ owned` 的申请；
- applications GET：同上；
- api-keys GET：仅返回 `agentId ∈ owned` 的密钥（通知派生随之收窄）；
- access-profile（管理变体）：caller 不在 owned → 403。
- 不以 `requestedBy == actor` 兜底放行：actor 改名/换人时历史申请不应随之漂移，持有关系
  以 Agent 绑定为准（文档明确此取舍）。

## 6. 管理 API 与审计

- `POST /admin-identities` 请求体新增 `ownedAgentIds`（可选，默认空）。
- 新增 `PATCH /admin-identities/{id}`：仅接受 `ownedAgentIds`（整体替换）。写
  `admin_identity.updated` 审计事件，metadata 携带 `added`/`removed`/`ownedCount`，不含
  任何密钥材料（沿用 created/disabled 的双语标签模式，i18n 同步补齐）。
- 管理权限：`platform_admin` 可改任意身份；`tenant_admin` 仅能改本租户身份且绑定范围
  校验同 §4；`security_reviewer` 只读。演示 `local-dev` 等同 platform。
- 控制台（管理侧 管理员身份页）：身份行新增持有调用方数，编辑弹窗提供调用方多选
  （仅列 local 调用方、按身份范围过滤）。

## 7. 会话响应

- `GET /auth/session` 响应新增 `holderAgentIds: string[]`：仅当已登录、非
  `platform_admin`、且 owned 非空时携带（其余场景省略，前端按"未收窄"处理）。
- 演示模式响应与今天逐字节等价（不新增字段）。

## 8. 前端

- `ConsoleSession` 增加 `holderAgentIds?: string[]`。
- `useAccessContext`：options 只保留 `callerInstanceId ∈ holderAgentIds` 的应用（holder
  会话下不再出现越权上下文；服务端 403 兜底）。
- `MineView` 调用方选择、`GoLiveView`/`ApplyView` 的上下文数据面：随服务端收窄自然生效，
  前端不再额外全量过滤（列表已窄）。
- 用户侧身份明示：侧栏身份区在 holder 会话显示「以 {actor} 身份 · 持有 {n} 个调用方」，
  i18n en/zh；演示侧栏维持「本地开发管理员」不变。
- 403 文案：持有者越权返回专用错误码（`HOLDER_SCOPE_DENIED`）与双语文案，前端经
  `apiErrorPresentation` 呈现（不落"证据/evidence"字样，遵守既有红线）。

## 9. 兼容与升级

- 迁移 016 纯增量；不绑定 = 行为不变（推荐语义下升级零破坏）。
- 存量部署升级路径：平台管理员按需为操作者身份绑定调用方 → 该身份重新进入用户侧即按
  持有者收窄；`platform_admin`/`security_reviewer`/演示模式不受影响。
- 回滚 = 换回旧二进制（新列有默认值，旧代码不读）。

## 10. 测试与验证

- httpapi：放行/拒绝矩阵（演示、platform、未绑定 tenant_admin、已绑定 tenant_admin、
  security_reviewer）；改绑即时生效（绑定后旧 caller 立即 403）；三类列表收窄；PATCH
  审计事件与权限边界；`HOLDER_SCOPE_DENIED` 文案。
- store：memory + PostgreSQL 的 `owned_agent_ids` roundtrip 与更新路径（PG 套件沿用空库
  假设）。
- 前端：session 类型与 options 过滤单测；i18n guard（新键 en/zh 齐全）。
- 浏览器：本地起**带身份种子**的实例（旁路条件不满足即 `requiresLogin=true`），分别以
  platform / 绑定的 tenant_admin / 演示三种会话走用户侧页面，双语验证身份明示与收窄。

## 12. 待拍板项

- **A（关键）空绑定语义**：推荐"回退租户范围"（§5）；若要最小权限默认（空绑定一律
  拒绝），需接受升级即破坏并补部署说明。
- **B PATCH 权限**：推荐 §6 的 platform 全量 + tenant_admin 本租户；可收紧为仅 platform。
  **已定（落地）：仅 platform**——既有管理员身份管理端点（创建/轮换/停用）全部是
  `requirePlatformAdmin`，PATCH 保持一致更收敛；tenant_admin 需要改绑时走平台管理员。
- **C security_reviewer 是否可被绑定**：推荐可绑定（评审者同时是某调用方负责人的场景
  真实存在），但绑定后其用户侧也收窄，审批队列不受影响（仍是管理面全量）。
