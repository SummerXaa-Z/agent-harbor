# AgentHarbor v0.6.0 Release Notes

Status: pending — backend core landed on main (PR #419), console wiring lands
with the PR that carries this file; v0.6.0 is tagged after that merge. Minor
release on top of v0.5.3: per-holder views close out the demo-identity #16
family. Adds schema migration 016; the API surface is additive and the
default behavior is unchanged until an identity is bound.

## Highlights

- Managed admin identities can be bound to caller agents (issue #16 family,
  backend in PR #419). A binding (`ownedAgentIds`) narrows the identity's
  user surface server-side: every permission-package journey endpoint
  (drafts, preflight, apply, approval requests, readiness, access handoff,
  tokens) and the management access-profile variant return
  `403 HOLDER_SCOPE_DENIED` for callers outside the binding, and the
  approval-request / application / agent-key lists are post-filtered to the
  owned callers. Rebinding takes effect on the next request — the owned set
  is looked up live per request, never cached in the session.
- Zero-breakage defaults. An identity without a binding keeps the existing
  tenant-scope semantics, so upgrading changes nothing until a platform
  administrator binds callers; `platform_admin`, bootstrap identities, and
  demo mode are unaffected. `security_reviewer` identities can be bound
  (their approval queue stays management-wide). Managed identities that go
  missing or disabled reject with 403, matching the existing disable
  semantics.
- Management and audit (platform-only, like the other admin-identity
  endpoints): `POST /api/v1/admin-identities` accepts `ownedAgentIds`, and
  the new `PATCH /api/v1/admin-identities/{id}` replaces the whole binding.
  Validation requires every agent to exist inside the identity's own
  management range (platform unrestricted, tenant-scoped roles limited to
  their tenant). Each change emits an `admin_identity.updated` audit event
  with the added/removed agent ids and the owned count — no key material.
- Console wiring (this PR). The console session consumes `holderAgentIds`:
  a bound non-platform identity sees 「持有 N 个调用方 / Holder scope: N
  callers」 in the sidebar, and the user-surface caller selector,
  access-context options, and journey views only offer its owned callers.
  The admin identities page shows the holder count per identity and an
  「持有调用方 / Edit holders」 modal (local callers only, scope-filtered,
  whole-replacement save with a success toast); bootstrap identities stay
  read-only. A stale cached context outside the binding renders the
  dedicated bilingual `HOLDER_SCOPE_DENIED` message instead of a generic
  error.

## Compatibility notes

- Adds migration 016 (`admin_identities.owned_agent_ids jsonb not null
  default '[]'::jsonb`) — purely additive with a default, so the old binary
  ignores it on rollback and no data backfill is needed.
- REST/MCP responses gain optional fields only (`ownedAgentIds` on
  admin-identity payloads, `holderAgentIds` on the console session when a
  bound non-platform identity is signed in). Demo-mode session responses are
  byte-identical to v0.5.3.
- Upgrade path: deploy, then bind operators' identities as needed from the
  admin console (or `PATCH`); each bound identity is narrowed from its next
  request. Unbinding restores tenant-scope visibility.
