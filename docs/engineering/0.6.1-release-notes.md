# AgentHarbor v0.6.1 Release Notes

Status: released 2026-10-03. Patch release on top of v0.6.0: the two
round-7 evaluation follow-ups — transient-refresh sample-row swap (E7-03,
PR #423) and cockpit environment-check scope copy (E7-04, PR #424) — plus
the round-7 evaluation archive and roadmap refresh (PR #422).
Frontend-and-docs only; no schema changes, no migrations, no API contract
changes, no backend changes.

## Highlights

- A transient refresh failure no longer swaps sample rows into a live
  console (round 7, E7-03, PR #423). `loadConsoleData` used to fall back
  per collection to fabricated sample rows on network errors, so one
  dropped GET could silently replace a live console's agents, grants, or
  audit views until a manual reload — matching round 7's intermittent
  "newly registered or disabled entries do not appear until reload". A
  transient failure now retains the previous real rows, and a new "stale"
  data status (distinct from "sample") drives a 「数据可能未更新 / Data may
  be outdated」 chip and banner with a retry action. Console reads send
  `cache: "no-store"` so a cached response can never masquerade as a
  refresh. Samples still appear before the first successful load only.
- The cockpit environment checks state their actual scope (round 7, E7-04,
  PR #424). "All registered targets reachable / 已注册目标均可访问"
  overclaimed: the automatic check probed the preferred target plus at most
  four other registered targets — warn-only, and skipped entirely when the
  backend lacks `target_probe_v1` — so the OK line was unfounded whenever
  probes were unsupported or more than five targets were registered. The
  automatic check is now scoped to the preferred target: the MCP
  tool-service row reads 「主目标 {endpoint} 在 {durationMs} 毫秒内响应 /
  Preferred target {endpoint} answered in {durationMs} ms」, and the
  environment-health row covers the management catalog only (「管理目录正常
  / Management catalog healthy」). The cockpit risk card no longer lists
  unreachable non-preferred targets; per-target verification remains in
  resource management's 「测试连接 / Test connection», and the probe-failure
  fix guidance points there. Verified in a browser with one healthy and one
  unreachable target registered: the cockpit stays scoped and quiet while
  the registry's test connection still reports the classified
  `UPSTREAM_CONNECT_ERROR` detail.
- The round-7 external evaluation record is archived with its triage in
  `docs/product/0.4.0-console-eval.md` (PR #422): functional pass on the
  released v0.6.0 baseline — main journey 10/10, readiness 11/11 with zero
  blocking items, the three specializations (per-holder views,
  grant-chain modal, handoff-config audit) correct, mobile 375/390px
  covered, security behaviors verified (masks only, separation of duties,
  holder-scope denial, revoke-to-401). Time-to-first-report was missed
  (~1h55m) on two environment issues (startup CORS recipe, externally
  terminated backend) rather than product ones; the EN spot-check and free
  exploration were deferred to round 8. The roadmap and README status were
  refreshed for v0.6.0 at the same time.

## Compatibility notes

- No migrations (still 016, unchanged since v0.6.0); upgrading is a binary
  swap, and rollback is the previous binary.
- No API contract changes; the release is frontend-and-docs only.
