# AgentHarbor v0.6.2 Release Notes

Status: released 2026-10-03. Quality release on top of v0.6.1 landing the
internal code-evaluation and audit follow-ups: the `internal/httpapi`
server.go split (PR #428), credential-encryption unit tests (PR #429),
frontend hardening (PR #430), the engineering docs map with a slimmer
README front door (PR #427), and a frontend code tidy (PR #426). No
schema changes, no migrations, no API contract changes.

## Highlights

- `internal/httpapi/server.go` — the 8,382-line catch-all — is split
  into 11 domain files plus a 556-line wiring core (PR #428). The move
  was mechanical, verified with exact line-multiset accounting (zero
  lines lost or duplicated), with no change to behavior, routing, or
  contracts. The frontend localization guard tests now scan the whole
  `internal/httpapi` package instead of a single file, so future moves
  cannot silently drop guarded copy.
- The console no longer white-screens on a render failure (PR #430). An
  app-scope error boundary wraps the console root and a route-keyed
  view-scope boundary wraps each page: a failing view shows a localized
  fallback card (explanatory hint, the error message, a working reload
  action), the shell and navigation stay alive, and switching away and
  back starts a fresh page. Verified in a browser against an injected
  render throw, including navigation away and back.
- Every console API request now carries a default 15-second timeout
  (PR #430): `requestSignal()` combines `AbortSignal.timeout` with an
  optional caller signal via `AbortSignal.any` across all three raw
  fetch sites, and a timeout abort classifies as a network failure so a
  hung backend degrades through the existing stale-data and fallback
  paths instead of pending indefinitely. The last three console data
  hooks without race guards (`useDailyMetrics`, `useAdminAudit`,
  `useConnectionDiagnostics`) also gained the same monotonic run-id
  guard as their 14 siblings, so a slow earlier request can no longer
  overwrite a newer one's rows — most visibly the audit timeline when
  switching ranges.
- A frontend lint gate is now part of every check (PR #430): oxlint with
  the correctness category runs in `make check`, `make release-check`,
  and CI ahead of the test step. Enabling it surfaced 20 findings, all
  fixed — dead imports, variables, and functions; three unstable
  `useMemo`s; and seven `exhaustive-deps` completions (including a
  latest-ref pattern in `useAccessHandoffController` that keeps its
  fetch effect keyed on the primitive filter key while reading the live
  filter).
- Credential encryption has own-package unit tests (PR #429, closing the
  security-audit coverage finding): round trip, nonce uniqueness,
  ciphertext-plaintext separation, wrong-key and tamper detection,
  truncated or wrong-size keys, and authenticated-but-not-JSON payloads
  for `EncryptCredentials`/`DecryptCredentials` — `internal/security`
  coverage 41.4% → 65.5%, with the deliberate empty-blob short-circuit
  pinned.
- The engineering documentation gained a technical map and an API
  reference, and the README front door was slimmed from 559 to 217 lines
  to route readers by intent (PR #427); duplicate frontend helpers were
  consolidated and import extensions aligned (PR #426).

## Compatibility notes

- No migrations (still 016, unchanged since v0.6.0); upgrading is a
  binary swap, and rollback is the previous binary.
- No API contract changes. The only backend change is the mechanical
  `internal/httpapi` file split; behavior, routing, and auth groups are
  unchanged.
- The console now aborts API requests after 15 seconds by default.
  Operators pointing the console at a slow upstream gateway should
  ensure responses complete within that window; the previous behavior
  waited indefinitely.
