# 控制台 UI 综合审查报告(视觉 / 体验 / 旅程 / 易用度 / 上手难度)

- **日期**:2026-06-11
- **分支**:`codex/production-readiness-gate`
- **范围**:Web 控制台全部 9 个工作区(权限变更 / 权限画像 / 上线证据 / 运行审计 / 系统自检 / Agent 与工具 / 工具能力 / 访问策略 / 路由规则),1365×882 桌面实测
- **方法**:本机 demo 环境(前端 5174 / API 9090 / MCP 8787)Chrome 逐页走查;完整操作一轮权限变更旅程(新建变更 → 提交审批 → 应用 → 完成态);前端源码静态阅读(`App.tsx` 4820 行、`styles.css` 3122 行、`i18n.ts` 1982 行)
- **与前序报告的关系**:本报告验收 [结构审查](permission-console-ux-review-2026-06-10.md)、[视觉审查](visual-design-system-review-2026-06-10.md)、[旅程审查](user-journey-review-2026-06-10.md) 三份 6 月 10 日报告的修复是否在 UI 上真实生效,并在已修复基线之上提出下一轮 finding。

> 总体判断:**比 6 月 10 日审查时的水位明显上了一个台阶。** 前几轮的 critical / high 基本闭环:侧边栏已是 200px 图标+文字三分组导航、核心选择器不再截断、旅程有了完成态、技术 ID 收进折叠区、配置生效后表单转只读。现在的问题不再是"廉价感"或"旅程断裂",而是**规模化前的结构债**和**一批中低优先级的体验毛刺**。本轮 **2 个 P1、3 个 P2、2 个 P3**,无 blocker。

## 实测确认做得好的

- **任务优先的信息架构**:默认落在"权限变更"而不是仪表盘;导航分"主流程 / 运行与审计 / 系统配置"三组,每项带一句说明。符合"管理员来这是为了完成一次变更"的定位。
- **状态机全程联动**:新建变更后,顶部状态条、右侧 1-5 步流程、审批区 badge、底部验收明细同步流转(需要审批 → 已批准 → 可上线),实测未发现状态打架。
- **完成态闭环**:可上线后给出绿色完成卡(含完成时间)+ 下载验收报告 / 查看权限画像 / 新建权限变更三个出口。6 月 10 日 j-4"旅程没有终点"已真实修复。
- **防误改**:生效后的配置转为"仅供复核"只读 + "新建权限变更"按钮,用户输入不会再被系统覆盖(j-1 修复有效)。
- **证据链可信**:上线验收页 9/9 检查、审批追溯带审批人和到期时间、管理审计逐条带操作者——产品核心卖点呈现到位。
- **工程纪律**:91 个前端单测、20 个场景脚本、release gate,每轮审查都有修复报告回链。

## Finding 明细

### ui-1(P1)— App.tsx 4820 行单体组件,后续所有 UI 迭代的成本放大器

全部 9 个页面、30+ 表单 state、所有 API 调用编排都在 [App.tsx](../../frontend/src/App.tsx) 一个文件里,仅拆出 5 个子组件(`AiAdminPermissionWorkbench` / `CapabilityGovernanceView` / `TenantAccessProfileView` / `ApprovalDropdown` / `TechnicalId`)。逻辑层已经拆得很干净(`coreJourney.ts`、`permissionPackages.ts` 等 20 个模块),唯独视图层没拆。

现状的代价:每修一个 UX finding 都要在 4800 行里定位,回归风险随改动次数累积;本报告 ui-2 的修复也必须先趟过这个文件。

**修法**:按 `NavKey` 把 9 个 view 拆成独立组件文件,App.tsx 只留 shell + 路由 + 共享 state,目标压到 500 行以内。纯结构移动,不改行为,91 个单测做安全网。

### ui-2(P1)— 结果消息是语言快照,切换语言后不刷新

实测:中文态提交审批产生"审批请求 ppar_… 已创建",切到 EN 后界面全英文,这条消息仍是中文。根因在 [App.tsx:425](../../frontend/src/App.tsx) —— `setAiAdminMessage(t(...))` 把**渲染后的字符串**存进 state,而不是存 key + 参数。全文件 `setAiAdminMessage` 调用均为此模式。对外演示双语能力时会露馅。

**修法**:state 改存 `{ key, params }`,渲染时再过 `t()`;`localizedErrorMessage` 同步改造。

### ui-3(P2)— Agent 注册表在真实数据量下会失控

当前 20 个种子 agent 几乎同名("Permission Package Approval Caller" × N),列表**无搜索、无过滤、无分页、无排序**;操作列只有"转为草稿 / 禁用"两个改状态按钮,没有"查看详情"。注册表是配置区使用频率最高的列表,上几十个真实 agent 后只能靠肉眼扫。工具能力页的能力列表同样问题——一长串重复的"查询客户 / 更新工单"行,无分组无搜索。

**修法**:两张表补名称关键字过滤 + 状态过滤;注册表按名称聚合或加创建时间排序;行上加详情入口(抽屉即可)。

### ui-4(P2)— "高级设置"一词承担三种语义

同一个折叠标签"高级设置"在三处含义不同:权限变更表单里是"技术 ID 覆盖"、运行审计每行里是"trace 技术详情"、权限画像查询区里是"租户/工作区过滤"。审计行里那个应改叫"技术详情"或"追踪详情";运行审计 20 行每行一个折叠,缺"全部展开"。

**修法**:按语义拆 i18n key(`advanced.override` / `advanced.traceDetail` / `advanced.filter`);审计列表加全部展开/收起。

### ui-5(P2)— 访问策略页的版面逻辑不直观

"访问策略"页左边是路由治理空状态,右边挂一整张管理审计表(与"路由规则"页底部的运行审计是另一张表)。策略为空时用户看到的主要内容是审计流水,容易误以为走错页。

**修法**:管理审计收为独立页或并入上线证据页;访问策略页空状态给"创建第一条策略"的引导动作(可跳路由规则页的创建表单)。

### ui-6(P3)— 系统自检页视觉密度失衡

自检步骤区字段标签和技术值挤在同一行("三级租户树tenant-root-ui-core-mq8y42yk -> …"),badge、说明、token 混排无对齐网格。受众是工程师,可读性可以低一档,但目前是全站唯一一眼看出"没排过版"的页面。

**修法**:标签/值两列网格,技术值统一 `--mono-font` + 截断 + copy 按钮(复用 `TechnicalId` 组件)。

### ui-7(P3)— 上手概念负担重,文档可读性拖后腿

产品有 9 个核心概念(租户 / 工作区 / 调用方 / 调用方实例 / 目标 / 能力 / 权限包 / 授权链 / 数据范围),README 只有文字版 core model 树,UI 内没有任何概念引导。README "Try the Permission Changes Console" 一段约 1000 字不分段不分点,新贡献者读不下去。`make demo` 一条命令起全套很好,但起来之后"我在看什么"靠用户自己悟。

**修法**:README 该段拆成编号步骤;权限变更页给一次性概念引导(空状态嵌一张 tenant → caller → capability → scope 示意图,或链接到 docs)。

### ui-8(P1)— 新用户打开空系统不知道下一步(已闭合)

后续实施计划见 [ui-8-first-run-journey-plan.md](ui-8-first-run-journey-plan.md)。本轮已新增 **开始使用** 工作区,用 6 步 checklist 呈现 `租户 -> Agent -> 能力 -> 授权 -> 运行时 -> 证据` 的首次配置链路;默认入口改为由 `frontend/src/gettingStarted.ts` 的纯函数判断,前 4 步未完成时进入"开始使用",已配置完成后仍默认进入"权限变更"主旅程。

**闭合实现**:

- 导航 IA 调整为"开始使用 / 接入配置 / 权限运营 / 审计与证据",组序与配置依赖顺序一致。
- "Agent 与工具"、"工具能力"、"授权链"和"运行审计"空状态新增下一步动作;过滤无结果仍只提示调整筛选,不误导跳转。
- 文案全部中英双语,沿用 key+params 渲染机制,没有新增语言快照 state。
- 未修改后端、未引入依赖;`ConsoleController.tsx` 净增 42 行,低于 +60 红线。

**实测结论(2026-06-11)**:

- 隔离 `make demo` 环境(`AGENT_HARBOR_DEMO_API_PORT=9093 AGENT_HARBOR_DEMO_FRONTEND_PORT=5175 MOCK_MCP_PORT=8793 VITE_API_BASE=http://127.0.0.1:9093`)无 hash 打开后,默认进入 `#getting-started`;页面显示"开始使用 / 搭好一条可用的权限链路",非示例模式,6 步 checklist 中 API 已完成、"注册租户与 Agent"为当前步骤。
- 同一 demo 环境跑完 `START_MOCK_MCP=false MCP_SERVER_MODE=real BASE_URL=http://127.0.0.1:9093 MOCK_MCP_PORT=8793 scripts/scenario-permission-package-approval.sh` 后,无 hash 打开默认进入 `#ai-admin`;页面显示"权限变更与状态检查",非示例模式,并保留完成态出口"导出证据 / 查看权限画像 / 新建权限变更"。
- 在已配置数据下手动打开 `#getting-started`,前 5 步完成,6 个行动按钮分别指向 `#getting-started`、`#registry`、`#capabilities`、`#ai-admin`、`#traces`、`#evidence`。第 6 步仍以 `evidenceRuns.length > 0` 判定;当前 `ConsoleData` 没有权限包 readiness 字段,因此权限包生产就绪不会被静默当作 checklist 完成。该字段边界需在后续把 readiness 纳入 `ConsoleData` 时再升级。
