# v0.7.0 M1 施工计划：自己先用起来（2026-11-04）

> 状态: Implementation plan，把 [ROADMAP M1](../../ROADMAP.md) 落成有顺序的 PR 清单与文件级任务。前置设计：[重设计](../product/2026-11-v2-redesign.md)、[组件设计](../product/2026-11-v2-component-design.md)、[UX 设计](../product/2026-11-v2-ux-design.md)。
> 语言: 施工阶段中文优先；合入主文档前按仓库惯例补齐中英双语。

## 目标与非目标

目标 = ROADMAP M1 验收：狗粮一周、审计页 1 分钟答「昨天干了什么」、一次真实 deny + 证据链、time-to-first-audit-event ≤ 5 分钟、strict 开关往返。非目标：wrap/SQLite/stateless 协议（M2）、策略库抽离（M3）、任何企业向特性。**M1 数据面仍是现有会话式 HTTP MCP 代理**——stateless 是 M2 的事。

## 施工顺序（六个 PR，依赖单向）

### PR-A：纯逻辑层 —— `internal/policy/`（无任何 IO 依赖）

- `schema.go`：harbor.yaml 的解析与严格校验（未知字段拒绝，报 file:line）；`workspaces[{id, strict, targets[], domains[]}]`、`agents[{id, workspace, allow[], deny[], subjects[]}]`。
- `evaluate.go`：`Decide(Request{workspace, target, tool, action: load|invoke, subject}) → Decision{allowed, reason, ruleRef, evidence[]}`，实现组件设计 §1 的七条语义 + 单一过滤器约束（tools/list 与 tools/call 共用）；glob 匹配独立函数。
- 测试：语义七条各至少一例、glob 边界、`go test -fuzz` 加 FuzzDecide；`make check` 增 schema 用例校验。
- 这是未来 harbor-policy（M3）的种子：包内禁止 import store/httpapi。

### PR-B：存储与 key —— migration 017 + store 双实现

- `internal/db/migrations/017_workspace_strict_and_audit_fields.sql`：workspaces 加 `strict`；audit 事件加 `args_digest`、`risk_flags`、`reason`（ruleRef 文本）；agent key 存储加哈希/前缀/作用域字段（先审计 014/016 现状再定列，已有一处 agent key 表——扩展而非重建）。
- store 仓储接口扩展 + memory/postgres 双实现（沿用现有接口模式）。
- key 签发/校验改哈希制：明文只在签发响应里出现一次。

### PR-C：服务端接线 —— 默认工作区 + 单一判定路径

- 首启动 seed 默认租户/工作区（存在即跳过）；`strict` 从 harbor.yaml 物化进 DB。
- data_plane 的 tools/list 过滤与 tools/call 判定**全部改走 `policy.Decide`**（删掉旧三层链的运行时判定路径——链表存储保留为账本，不再参与判定）。
- deny 响应在 MCP 错误结构中带 `{policy, reason, auditId}`；成功/拒绝事件统一写新审计字段（argsDigest、riskFlags：capability.action ∈ {delete,write,export,admin} ∨ 名称模式）。
- 无头模式：`AGENT_HARBOR_DISABLE_WEB=true` 跳过控制台资产。
- 高危标红数据就位（M1 的标红先出在 CLI/API，页面在 PR-F）。

### PR-D：CLI 骨架 —— 子命令与退出码规范

- 入口决策：新增 `cmd/harbor`（`harbor serve` 启服务），`cmd/agent-harbor` 保留一个版本周期作别名。子命令用标准库 flag 自写分发，不引依赖。
- 实现：`serve`、`init`、`apply [--dry-run]`、`audit [--follow|--high-risk|--json]`、`why <id>`、`key issue/rotate/revoke`。退出码按 UX 设计 §2（0/2/3/4）。
- `--follow` 用现有审计查询接口轮询+去重（SSE 不引入）。

### PR-E：import 与 connect —— 采纳漏斗

- 客户端注册表 `internal/clients/registry.yml`（抄 Docker schema：installCheckPaths/分 OS 路径/list-set-del），冷启动清单照搬 Docker 的表。
- `harbor import`：扫描（servers.json → Claude Code → Codex）→ 目标提议 → 凭据迁移（internal/security 加密，`--confirm`，值不回显）→ 生成初始 harbor.yaml（宽松、全入圈）→ 预注册 agent + 一次性 key。
- `harbor connect <client>`：按注册表写客户端配置（server 名不变），`--print` 兜底；幂等（重跑出 diff）。
- Go 侧写 JSON/YAML 配置文件用保留原格式的最小编辑（JSON 原地改 key；TOML 仅 Codex 一个特例手写处理器）。

### PR-F：控制台两页 —— 时间线与解释器

- 审计时间线重做为默认页：my-agents 视角（按 agent+时间）、高危红标、来源徽标字段（M1 恒为 gateway）、`仅高危`过滤、搜索。
- 证据链抽屉 = 决策解释器（复用现有 evidence/chip UI，数据来自新 reason/ruleRef 字段）。
- 冻结视图隐藏：非多租户 flag 下侧边栏只出时间线+解释器两入口。
- i18n 双语键补齐；vitest 组件测试跟上（时间线行渲染、抽屉证据步、红标过滤）。

## 狗粮切换（PR-F 合并后当天）

1. `harbor import` 扫真机配置 → `connect claude-code codex` → 重启客户端。
2. 范围声明：**M1 狗粮只覆盖 HTTP MCP 目标**（stdio 目标维持直连，M2 wrap 接手）——验收里的「两个客户端」指 HTTP 流量。
3. 每日仪式跑起来：`harbor audit --follow`、周末 `harbor review --week`（review 引擎可后置到狗粮第二周）。
4. 回退：客户端配置把端点改回原值即退出狗粮（server 独立进程，不影响存量）。
