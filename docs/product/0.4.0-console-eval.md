# AgentHarbor 0.4.0 重设计管理控制台外部验收报告

- 评估对象：AgentHarbor 0.4.0 重设计控制台
- 前端入口：`http://127.0.0.1:15174/`
- 后端 API：`http://127.0.0.1:19090`
- 真实 MCP 服务：`http://127.0.0.1:18787/mcp`
- 评估时间：2026-09-27
- 报告语言：中文
- 验收方式：界面走查、接口核验、真实 MCP 网关调用、R1–R8 回归、中英抽查与自由探索

## 一、总体结论

**本轮外部验收结论：不通过，不建议将 0.4.0 重设计控制台直接作为默认新版发布。**

0.4.0 的信息架构、资源注册、能力审批、三层授权、短期令牌和网关执行链路已经具备较完整的产品形态；R1–R8 回归项均取得通过证据，网关在持有合法短期令牌时能够完成真实 MCP 调用，并能对错误主体、缺失主体、未授权能力和已撤销令牌进行拦截。

但自然用户路径存在两个发布级阻断：

1. **新发现 MCP 能力默认缺少数据域，导致权限模板预览将本应允许的读写能力全部阻止。**
2. **Access Handoff 要求先有允许/拒绝运行记录才能创建短期令牌，而网关又要求 Bearer Token，界面内没有自举路径，形成启动死锁。**

此外，真实 MCP 上游在网络可达且请求方携带正确 MCP `Accept` 头时，可绕过网关直接完成 `initialize` 与 `tools/call`。如果部署边界假设网关是唯一入口，该问题会削弱治理与审计闭环。

下游网关、令牌生命周期和真实 MCP 调用是通过**临时 Agent Key 旁路**完成验证的；临时 Key 与正式短期令牌均已在收尾时撤销。该旁路可证明后端能力成立，但不能视为自然主流程通过。

## 七、自由探索新发现

### #24 新发现 MCP 能力默认缺少数据域，导致模板预览错误

- 严重级别：P1
- 步骤：刷新 MCP 目标能力后，不做额外治理，直接使用 `support-ticket-triage` 模板预览权限包。
- 现象：预览显示“允许 0 · 阻止 3”，模板声明允许 read/write，但 `search_customer` 与 `update_ticket` 均被判定不匹配。接口预览返回相同结果。
- 根因：新发现能力初始 `dataDomains` 为空，模板按数据域匹配时全部失败。
- 预期：能力发现时应根据模板默认数据域、目标配置或管理员引导完成必填治理；未完成时应明确提示“缺少数据域”，而不是显示模板阻止了本应允许的能力。
- 本轮临时处置：手动将三项能力归类为 `support`。

### #25 Access Handoff 存在自然路径启动死锁

- 严重级别：P0
- 步骤：权限包应用后进入“我的上线”，尝试创建短期令牌。
- 现象：上线报告要求先具备一次允许运行记录和一次拒绝运行记录；没有记录时“Create short-lived token”按钮禁用。网关调用又必须携带 Bearer Token，未携带时返回 HTTP 401 `missing bearer token`。界面内未提供自举调用入口。
- 直接接口结果：创建短期令牌返回 `409 ACCESS_HANDOFF_NOT_READY`。
- 预期：应提供受控的试运行/预检调用通道，或允许首次引导令牌仅用于生成规定能力的允许/拒绝证据；不能让用户在“没有令牌不能调用、没有调用不能发令牌”中循环。
- 本轮旁路：创建临时 Agent Key 产生运行证据后立即撤销。

### #26 真实 MCP 上游可在正确 Accept 头下绕过网关直接调用

- 严重级别：P0（若网关被设计为强制治理入口）
- 步骤：直接访问 `http://127.0.0.1:18787/mcp`，先发送 `initialize`，再发送 `tools/call`。
- 现象：不带 MCP 要求的 Accept 头时返回 HTTP 406；携带 `Accept: application/json, text/event-stream` 后，`initialize` 返回 HTTP 200，直接调用 `update_ticket` 也返回 HTTP 200，响应包含 `source: real-mcp-sdk`、`updated: true`。
- 预期：需要在部署文档中明确 MCP 上游必须仅绑定网关可达地址，或在上游增加认证、网络 ACL、调用方身份校验；否则网关授权、主体限制和审计可被绕过。

### #27 无效路由与无效资源深链缺少明确“未找到”反馈

- 严重级别：P2
- 步骤：访问不存在的路由、不存在的资源深链或审批深链。
- 现象：无效 hash 未显示 404，而是落到旧版 `#getting-started` 或现有页面；无效资源深链未弹出资源详情，也未提示“未找到”。
- 预期：应显示“页面不存在 / 资源不存在”，提供返回首页或资源列表入口，并保留原始深链用于排障。

### #28 命令面板近期资源包含停用资源且无状态警示

- 严重级别：P2
- 步骤：打开命令面板查看 RECENT / 近期资源。
- 现象：`Zero Capability Target`、`Unreachable Target Case`、超长名称资源等停用资源出现在近期资源中，未显示 Inactive/Disabled 状态。
- 预期：近期资源应显示状态徽标；停用或不可达资源默认弱化展示，避免用户误点。

### #29 停用目标仍可测试连接并显示成功

- 严重级别：P2
- 步骤：对状态为 disabled 的目标 `agt_86d1ee5a1737479aca0d8361f06cfaa2` 执行 probe。
- 现象：接口返回 `status=ok`、`httpStatus=200`、`toolCount=3`，未提示该目标在控制平面已停用。
- 预期：停用资源可以允许管理员手动强制探测，但默认应提示“资源已停用，当前仅验证网络连通性”，或直接阻断非管理员操作。

### #30 资源头部计数将停用目标计入

- 严重级别：P3
- 步骤：进入资源管理页查看头部统计。
- 现象：页面显示 `1 callers · 5 targets`，但 5 个目标中只有 1 个 Active，其余为 Inactive。
- 预期：主计数应默认展示 Active 数量，或同时展示“总数/启用数”，例如 `5 targets · 1 active`。

### #31 运行审计中的工具调用行缺少详情入口

- 严重级别：P2
- 步骤：进入“运行审计”，查找 `Tool call (allowed)` 或 `Tool call (denied)` 行。
- 现象：普通资源变更事件有“Details”，但工具调用行仅显示摘要，如 `Permission assignment matched` 或 `PERMISSION_DENIED...`，没有详情按钮。
- 预期：应能从工具调用行进入 Trace 详情，串联请求 ID、决策、策略、租户授权、工作区分配、调用方授权、上游请求和响应摘要。

### #32 未重新检查即导出报告可能得到旧 blocked 摘要

- 严重级别：P2
- 步骤：权限状态变化后不点击 Re-check，直接导出验收报告。
- 现象：可能导出仍为 blocked 的旧摘要，文件名中保留旧 digest，容易与最新状态混淆。
- 预期：导出前应自动刷新检查结果，或在报告中显著标注“基于何时的检查快照”；若状态可能过期，应阻止导出并提示重新检查。

### #33 已应用后修改快照字段，界面提示需审批但没有提交入口

- 严重级别：P2
- 步骤：权限包应用后修改区域或申请说明等快照字段。
- 现象：界面识别为需要审批，但未提供“提交审批”按钮；只能直接调用后端接口创建新的审批请求。
- 预期：应提供“基于当前修改创建新审批”的入口，或明确说明哪些字段仅为备注、不会触发新审批。

### #34 新创建 draft 资源在列表中出现不稳定

- 严重级别：P2
- 步骤：通过注册弹窗创建长名称 draft 目标后返回资源列表。
- 现象：初次列表未稳定显示新 draft 资源，可能导致用户无法从界面继续编辑或启用；刷新或重新进入后才出现。
- 预期：创建成功后应即时插入列表，或给出“草稿已保存，正在刷新”的明确状态。

### #35 中文界面模板描述与英文界面用户内容存在混排

- 严重级别：P3
- 步骤：中文界面查看权限模板卡片；英文界面查看中文申请记录。
- 现象：中文界面模板描述保留大段英文；英文界面中用户填写的中文申请说明直接显示且无原文标识。
- 预期：中文模板描述应完整翻译；英文界面对用户生成的中文内容可标注“Original language content / 原文内容”，必要时提供辅助翻译。

### #36 跨面切换按钮未展示另一面未读数

- 严重级别：P2
- 步骤：在管理面产生待审批通知后切换到用户工作台。
- 现象：铃铛显示未读，但“Go to admin console / 前往管理控制台”按钮没有未读角标。
- 预期：面切换按钮应展示另一面未读数，帮助用户理解当前未读属于哪个工作台。

### #37 未指定或跨租户同名资源可形成 default 租户重复记录

- 严重级别：P2
- 步骤：资源注册时未明确选择租户，或在不同租户上下文中使用相同名称注册。
- 现象：同租户/工作区重复注册返回 409，但未指定租户的同名资源曾被接受，在 default 租户下形成另一个 `MCP Demo`，后续已禁用。
- 预期：当表单缺少租户时应阻止提交；若产品允许跨租户同名，应在资源列表和重复校验提示中明确租户范围，避免演示环境出现默认租户影子资源。

## 2. 三视角观察

### 2.1 平台工程师视角（接入配置 / 服务可用性 / 错误可诊断性）
接入路径顺畅：建租户→注册目标→测试连接（"可达 — HTTP 200 / 3 个工具,7ms"）→刷新能力→建授权链，全程有明确引导。复制的 shell 脚本含完整主机、用 `read -rs` 粘贴令牌、curl 可直接执行；标准 MCP streamable-http 客户端按"复制配置"接入（注意需为相对 url 补 origin，#39）。错误信息可诊断性强：不可达端点返回 **分类码 `UPSTREAM_CONNECT_ERROR` + 类别短语 + 技术原因**（"upstream connection failed: dial tcp 127.0.0.1:9: connect: connection refused"），驾驶舱"修复指引"给出"恢复目标服务,或取消注册"。运行时真实调通：合规 update_ticket 200、越权/无主体 403、撤销后 401，状态码与文案一致。

## 6. 新发现列表（#38 起）

### #38 审批详情不渲染"允许"的能力，仅渲染拒绝护栏 — 严重度：中（安全评审可核对性）
- **步骤**：变更审批中打开任一申请详情（本次为已批准 `ppar_3531db5a…`）。
- **现象**：详情列出申请人、主体、审批人、范围、调用链路、权限包模板、申请时间，随后**只显式列出被拒绝的护栏 `delete-ticket / 拒绝`**；**未显式列出"允许"的能力 Update Ticket**。完整 API 记录里有 `allowedCapabilityIds=[cap_ecd55c48…]`，但界面未渲染。
- **预期**：审批详情应同时列出"允许"项（能力名称/键）与"拒绝"项，使审批人无需查 API 即可核对本次变更到底放开了什么。

### #39 "复制配置"的 url 为相对路径，脱离控制台源站不可直接调用 — 严重度：低
- **步骤**：我的上线 → 接入交付，点"复制配置"。
- **现象**：剪贴板 JSON 中 Authorization 为占位符 `Bearer ${AGENT_HARBOR_TOKEN}`（正确），但 `"url": "/api/v1/mcp/agents/agt_251879…/rpc"` **为相对路径、无主机**。
- **预期**：复制的配置应含完整 origin（如 `http://127.0.0.1:19090/api/v1/...`），与"复制"得到的 shell 脚本（含完整主机）保持一致，便于在远程/标准 MCP 客户端直接使用。

### #40 空态派生的环境通知在条件解除后仍常驻未读 — 严重度：低
- **步骤**：初次空态加载产生"环境检查失败：尚未注册 MCP 目标 / 还没有权限申请记录"；随后完成目标注册与申请批准。
- **现象**：这两条环境通知在条件已解除后**仍以未读常驻**，直到手动点"全部标记已读"才清除。
- **预期**：派生通知宜标注生成时点，或在对应条件解除后不再作为待读提示（主动生命周期可归入已知"通知第二期"，此处仅指当前前端派生项的时效性）。

## 8. 自由探索新发现（自 #41 起）

### #41【中 · 健壮性 / 错误可诊断性】运行验证在"拒绝探针未返回 403"时静默中止、死锁在 9/11 且无任何用户可见报错

- **步骤**：当调用方的**授权宽于即将应用的权限包**时触发——本轮首次走查误建了 Export Contracts 授权链（能力弹窗默认选中 Export），随后才建 Update/Search，共 3 链；此时执行自动运行验证。
- **现象**：拒绝探针调用 `export_contracts` 时，因已存在 Export 授权链，网关未按预期 403 拦截，而是透传到上游返回 **HTTP 200 + MCP -32602 参数错误**（"Invalid option: expected one of csv|json at format"）。前端对"拒绝探针应得 403"的断言失败后**中止后续序列**（允许探针未执行、临时密钥被删除），就绪**停在 9/11**，"创建短期令牌"按钮**禁用**，且**界面没有任何用户可理解的报错或恢复指引**（经注入 fetch 拦截器才定位到根因）。授权链无 DELETE 端点，普通用户无法自助回退。
- **预期**：探针实际状态与预期不符时，应给出明确错误（哪个能力、观察到的状态码/响应 vs 预期），继续执行其余探针或提供可操作的恢复路径（如提示"存在宽于权限包的授权，请收敛或忽略此探针"），而非静默中止并把用户困在禁用态。
- **备注**：本发现源于评估中一次误操作，但对应"授权宽于权限包"是真实可出现的配置；在干净的 2 链数据上主旅程正常（11/11）。建议作为错误可诊断性改进登记。

### #42【低 · 一致性 / 文案】自检页聚合"修复指引"弹窗缺少单目标的分类技术原因

- **步骤**：注册不可达目标并运行环境检查，点击自检环境行的"修复指引"，再到资源页对同一目标点"测试连接"。
- **现象**：聚合弹窗仅显示"1 个已注册目标不可达 / 恢复目标服务，或取消注册。/ broken-mcp (http://127.0.0.1:59999/mcp)"，**未含**分类码与技术原因；而"测试连接"弹窗明确给出 `UPSTREAM_CONNECT_ERROR … dial tcp … connection refused`。
- **预期**：两处对同一不可达根因给出一致的分类 + 技术细节（或在聚合弹窗中展开单目标详情），减少排障跳转。
